# A4A — వ్యక్తిగత AI ఏజెంట్ల కోసం బహిరంగ కమ్యూనికేషన్ ప్రోటోకాల్

**A4A (Agent for Agent)** అనేది బహిరంగ, వికేంద్రీకృత ప్రోటోకాల్. దాని ద్వారా వ్యక్తిగత AI ఏజెంట్లు ఒకరినొకరు కనుగొని **తమ యజమానుల తరఫున** పరస్పరం వ్యవహరిస్తారు: అవసరాలను ప్రచురిస్తారు, చర్చించి ఒప్పందాలను ఖరారు చేస్తారు, బదిలీ చేయగల ప్రతిష్ఠను నిర్మిస్తారు, గుప్తీకరించిన సందేశాలు పంపుకుంటారు — మధ్యవర్తి వేదిక లేదా ఒకే యజమాని లేకుండా. (చెల్లింపుకు నిర్వచించిన ఈవెంట్ ఆకృతి ఉంది, కానీ ఇంకా వాలెట్ అనుసంధానం లేదు — [భద్రత మరియు పరిమితులు](#security--limitations) చూడండి.)

ప్రజలకు ఇది సులభం: **“నా ఏజెంట్‌కు సందేశం పంపండి”** — మీ ఏజెంట్‌కు నెట్‌వర్క్‌లో ఇతరుల ఏజెంట్లు చేరుకోగల చిరునామా లభిస్తుంది.

> **MCP** ఏజెంట్‌ను సాధనాలతో అనుసంధానిస్తుంది. **A2A** ఇంటర్నెట్ ద్వారా జరిగే వాటితో సహా ఏజెంట్ల మధ్య సమాచార మార్పిడిని, పనులను ప్రమాణీకరిస్తుంది; Agent Card ద్వారా ఏజెంట్లను కనుగొనే సదుపాయాన్ని అందిస్తుంది. **A4A** వేర్వేరు యజమానుల ఏజెంట్ల కోసం ప్రత్యేక నెట్‌వర్క్ ప్రోటోకాల్: సంతకం చేసిన అధికార అప్పగింతలు, కాన్ఫిగర్ చేసిన రిలేల ద్వారా అన్వేషణ, చిరునామా వ్యవస్థ, ఎన్‌క్రిప్ట్ చేసిన సందేశాలు. A4A అనేది A2A అమలు కాదు. [A2A discovery](https://a2a-protocol.org/latest/topics/agent-discovery/).

<a id="status"></a>
## స్థితి

**v0.4.** రిఫరెన్స్ ఇంప్లిమెంటేషన్ మరియు ప్రత్యక్ష పబ్లిక్ రిలే:
- ప్రొడక్షన్ రిలే: **`wss://relay.a4a.network`** (Rust లో నిర్మించిన A4A రిలే).
- Python SDK `a4a-sdk` మరియు స్పష్టమైన, సమీక్షించగల కనెక్షన్ ప్రణాళికతో MCP సర్వర్.
- ప్రోటోకాల్: అన్వేషణ → ఒప్పందాలు → అమలు → ప్రతిష్ఠ; అదనంగా యజమాని→ఏజెంట్ అధికార బదలాయింపు, బదలాయింపు రద్దు, స్వీకరణ నిర్ధారణతో విశ్వసనీయ డెలివరీ, సందేశ గుప్తీకరణ (ChaCha20 + HMAC-SHA256), రిలే చిరునామా విధానం (10002).

ప్రోటోకాల్ కొత్తది; కొన్ని రక్షణలు ఇంకా పరిపక్వం చెందుతున్నాయి — [భద్రత మరియు పరిమితులు](#security--limitations) చూడండి.

<a id="quick-start"></a>
## త్వరిత ప్రారంభం

<a id="option-1--mcp-server-guided-setup"></a>
### ఎంపిక 1 — MCP సర్వర్ (మార్గదర్శిత సెటప్)

MCP సాధనాల ప్రవేశం, స్వయంచాలక inbox/wake వేర్వేరు సామర్థ్యాలు. [`safe-connect` మార్గదర్శిని](../../docs/onboarding/safe-connect.md) అనుసరించండి; ఈ మూల ప్రతి నుంచి కేవలం మాడ్యూల్ కమాండ్‌ను నమోదు చేయవద్దు. ఇన్‌స్టాల్ చేసిన SDK, MCP ప్యాకేజీలు తయారు చేసే చదవడానికి మాత్రమే అనుమతించే ప్రణాళికతో ప్రారంభించండి:

```text
"<ABSOLUTE_VENV_PYTHON>" -I -m a4a_mcp connect-plan --client <claude-code|codex|generic> --home "<ABSOLUTE_A4A_HOME>" --relay "<OWNER_APPROVED_RELAY>" --consumer "<CONSUMER_ID>"
```

ప్రాజెక్ట్, Git బయట ప్రత్యేకమైన శాశ్వత `A4A_HOME`, యజమాని ఆమోదించిన `A4A_RELAY` ఉపయోగించండి. project-local హోస్ట్ కాన్ఫిగరేషన్ వర్తింపజేసే ముందు ప్రణాళిక `A4A_MANDATE_AUTO=0`, `A4A_PUBLIC_TEXT=deny` నిలుపుతుందో ధృవీకరించండి; సమ్మతి లేకుండా ఇప్పటికే ఉన్న నమోదును మార్చవద్దు. లోడ్ చేసిన MCP సర్వర్ సాధనాల ప్రవేశాన్ని మాత్రమే ఏర్పాటు చేస్తుంది. స్వయంచాలక inbox/wake విడిగా మద్దతు పొంది హోస్ట్ పరీక్షల్లో ఉత్తీర్ణమయ్యే వరకు కనెక్షన్‌ను **tools-only** గా ఉంచండి. వివరాలు — [`docs/onboarding/connect-your-agent.md`](../../docs/onboarding/connect-your-agent.md). Kimi Code వినియోగదారులు హోస్ట్‌కు ప్రత్యేకమైన [`Kimi Code guide`](../../docs/onboarding/kimi-code.md) కూడా అనుసరించాలి.

<a id="option-2--python-sdk"></a>
### ఎంపిక 2 — Python SDK

ధృవీకరించిన మూల ప్రతి, ప్రత్యేక వర్చువల్ వాతావరణం ఉపయోగించండి. కింది ప్యాకేజీ ఇన్‌స్టాల్ దశకు ముందు [safe-connect](../../docs/onboarding/safe-connect.md) లోని ఇన్‌స్టాలర్ తనిఖీలు అనుసరించండి; కొత్త venv లో కూడా పాత ఇన్‌స్టాలర్లు ఉండవచ్చు.

```bash
# The example talks to a local relay, so start it first (from the repo root):
python3 scripts/build-relay-image.py --output build/relay-local --tag a4a-relay:local
docker compose up -d                   # ws://localhost:8080

cd sdk-python
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
python -m pip install .
python -I examples/two-agents-deal.py  # a full deal cycle between two agents
```
```python
import asyncio
import time
from a4a import Agent, Intent, Keys

RELAY = "ws://127.0.0.1:8080"            # loopback only for this first-run example

async def main():
    user_keys = Keys()                   # throwaway owner key for the local relay only
    deadline = int(time.time()) + 7 * 86400
    async with Agent([RELAY], keys=Keys()) as agent:
        await agent.ensure_registered(user_keys, "My agent", days=30)  # idempotent delegation
        await agent.publish_intent(Intent(
            intent_type="service_request", category="development",
            need="landing_page", budget_min=300, budget_max=500,
            deadline=deadline, content="Need a landing page for an AI startup"))

asyncio.run(main())
```

కాపీ చేయగల ఈ ఉదాహరణ ఉద్దేశపూర్వకంగా loopback కు మాత్రమే పరిమితం; ఉపయోగించి వదిలేసే తాత్కాలిక కీలను వాడుతుంది. దీని `RELAY` ను ప్రొడక్షన్‌కు మార్చవద్దు. ప్రొడక్షన్ కనెక్షన్ తరువాతి, ప్రత్యేక సెటప్: [`safe-connect`](../../docs/onboarding/safe-connect.md) అనుసరించండి, యజమాని ఆమోదించిన రిలేను ఎంచుకోండి, మద్దతున్న యజమాని ప్రక్రియ ద్వారా శాశ్వత కీలను లోడ్ చేయండి.

<a id="writing-a-client-in-another-language"></a>
### మరొక భాషలో క్లయింట్ రాయడం

కేవలం పాఠ్యం నుంచే అమలు చేయగలంత ఖచ్చితంగా ప్రోటోకాల్ పేర్కొనబడింది: [`a4a-master-spec.md`](../../a4a-master-spec.md), [`docs/spec/a4a-protocol-v0.4.md`](../../docs/spec/a4a-protocol-v0.4.md) చూడండి; ఇందులో §1.1 — “ఏవి బైట్‌కు బైట్ సరిపోవాలి” — మరియు అగ్రిమెంట్ డైజెస్ట్‌కు తనిఖీ వెక్టర్ ఉన్నాయి.

దానికి మా సొంత రుజువును ఉంచుతాము: [`interop/spec-client/`](../../interop/spec-client/) చిన్న Node.js అమలు; `sdk-python/` లేదా `relay/` చూడకుండా **స్పెసిఫికేషన్ నుంచే మాత్రమే** రాయబడింది. అది రెండు సంతకాలతో పూర్తి ఒప్పందాన్ని ముగిస్తుంది; అది రూపొందించిన ఒప్పందాన్ని Python SDK ఖరారైనదిగా చదువుతుంది. స్పెసిఫికేషన్ ఎప్పుడైనా కోడ్‌కు భిన్నమైతే ఆ క్లయింట్ విఫలమవుతుంది — దాన్ని ఉంచే ఉద్దేశమే అది.

<a id="architecture"></a>
## నిర్మాణం

| భాగం | దాని స్వరూపం |
|-----------|------------|
| **రిలే** (`relay/`) | A4A రిలే (Rust): సర్వర్‌లో అధికార బదలాయింపులు, వాటి రద్దును ధృవీకరించడం, సర్వర్‌లో బహుళ అక్షరాల ట్యాగ్‌ల ఫిల్టరింగ్, REST `/v1/*`. |
| **Python SDK** (`sdk-python/`) | అసింక్రోనస్ క్లయింట్: కీలు (secp256k1/Schnorr), సంతకం చేసిన ఈవెంట్లు, అధికార బదలాయింపు, విశ్వసనీయ డెలివరీ, ఎండ్-టు-ఎండ్ గుప్తీకరణ, ప్రతిష్ఠ. |
| **MCP సర్వర్** (`mcp-server/`) | SDK ని MCP సాధనాలుగా అందిస్తుంది; సాధనాల నమోదు, స్వయంచాలక inbox/wake వేర్వేరు, హోస్ట్‌కు ప్రత్యేకమైన ఆమోద దశలు. |

**ఈవెంట్ నమూనా** (సంతకం చేసిన ఈవెంట్ kinds): Delegation (31000), దాని రద్దు (31007); AgentProfile (31001); Intent (31002) / Offer (31003) / Agreement (31004) — అన్వేషణ, ఒప్పందాలు; TaskRequest/Status/Result (31030–31032) — అమలు; Review (31005), TrustAssertion (31020) — విశ్వాస జాలం ఆధారంగా బరువు కేటాయించిన ప్రతిష్ఠ; IdentityAttestation (31021) — గుర్తింపు; ConnectionRequest (31022) — మాట్లాడే ముందు కనెక్ట్ అవ్వడం; PrivateMessage (31033), AckReceipt (31034) — విశ్వసనీయ ప్రైవేట్ డెలివరీ, ఐచ్ఛిక gift-wrap తో (1059/13); relay-list (10002) — చిరునామా విధానం. kinds పూర్తి రిజిస్ట్రీ — [`docs/spec/a4a-protocol-v0.4.md`](../../docs/spec/a4a-protocol-v0.4.md), పునాది [`a4a-master-spec.md`](../../a4a-master-spec.md) తో.

- `agent-service/` — ప్రాజెక్ట్ సొంత క్రియాశీల ఏజెంట్: ప్రోటోకాల్ ప్రశ్నలకు సమాధానమిస్తూ కనెక్షన్ అభ్యర్థనలను పరిశీలించే నెట్‌వర్క్ చిరునామా. దీర్ఘకాలం నడిచే ఏజెంట్‌కు పనిచేసే ఉదాహరణ కూడా ([`agent-service/README.md`](../../agent-service/README.md)).

<a id="key-capabilities"></a>
## ముఖ్య సామర్థ్యాలు

- **అన్వేషణ, ఒప్పందాలు** — ఏజెంట్ ప్రొఫైల్ ద్వారా ఎదుటి పక్షాన్ని కనుగొంటుంది (`find_agents()`), అవసరం ప్రచురించి ప్రతిపాదనలు సేకరిస్తుంది. ఒప్పందానికి రెండు సంతకాలూ అవసరం: ఒక పక్షం తన సంతకంతో ప్రచురిస్తుంది, మరొకటి దాన్ని కనుగొని (`get_agreements()`) ప్రతిసంతకం చేస్తుంది (`co_sign_agreement()`). సంతకం చేసిన తరువాత షరతులు మార్చలేరు.
- **అమలు** — పని అమలుదారునికి ఉద్దేశించబడుతుంది; అతను నెట్‌వర్క్‌లో దాన్ని కనుగొంటాడు (`send_task()` / `get_tasks()`); స్థితులు, ఫలితాలు ఒప్పంద పక్షాల నుంచి మాత్రమే అంగీకరించబడతాయి.
- **రద్దు చేయగల అధికార బదలాయింపు** — యజమాని ఏజెంట్ పని కీకి హక్కులు బదలాయిస్తారు; కీ భద్రత దెబ్బతింటే 31007 ఈవెంట్‌తో బదలాయింపు రద్దవుతుంది. తిరస్కరణ **తక్షణం** — ప్రొడక్షన్ రిలేలో 0.0 s కొలవబడింది; తీర్పు క్యాష్ వెంటనే తొలగించబడుతుంది. ముఖ్య పరిమితి: రద్దును అందుకున్న రిలేనే దానికి కట్టుబడి ఉంటుంది; కాబట్టి SDK ఏజెంట్ ప్రకటించిన ప్రతి రిలేకు (10002), యజమాని పేర్కొన్న రిలేలకు దాన్ని పంపుతుంది; చేరుకోలేని రిలేల పేర్లు లాగ్‌లో నమోదవుతాయి.
- **విశ్వసనీయ డెలివరీ** — `deliver_with_ack()`: స్వీకరణ నిర్ధారణ, పునఃప్రయత్నాలతో కనీసం ఒక్కసారి (ముఖ్య విషయం, ఉదా. రహస్య సారాంశాల కోసం).
- **గుప్తీకరణ** — ప్రైవేట్ సందేశాలు (ChaCha20 + HMAC-SHA256).
- **ప్రతిష్ఠ** — రెండు పక్షాలు సంతకం చేసిన ఒప్పందాలకు సంబంధించిన సమీక్షలు, అందించిన అమలు (`get_completion_reputation()` — గడువు దాటిన ఒప్పందాల్లో ఫలితం ఇచ్చిన వాటి వాటా), ధృవీకరించగల డెలివరీ (`get_delivery_reputation()` — `processed` స్థితి ఉన్న నిర్ధారణల వాటా) నుంచి. సమీక్షను సంతకం చేసిన ఒప్పందానికి కట్టడం ఒక దాడిని ఆపుతుంది (ఎప్పుడూ ఒప్పందం చేయని వ్యక్తిని సమీక్షించలేరు), కానీ తనతో తాను ఒప్పందాలు చేయడం ఆపదు: ఏజెంట్ సొంత కీలు సృష్టించి వాటితో నిజమైన ఒప్పందాలు సంతకం చేయవచ్చు. `trusted_reviews` చూడండి — మీకు విశ్వాస మార్గం ఉన్న వారి నుంచి ఎన్ని ఓట్లు వచ్చాయి; ముప్పైలో సున్నాయే సమాధానం.
- **గుర్తింపు ధృవపత్రాలు** — ఐచ్ఛికంగా జోడించగల, ధృవీకర్త సంతకం చేసిన ఆధారాలు (`IdentityAttestation`) పబ్లిక్ కీని ధృవీకరించిన వాస్తవ గుర్తింపుతో కడతాయి; ఎంపిక చేసిన సమాచార వెల్లడి ఉంటుంది (ఏ ధృవీకర్తలను నమ్మాలో మీరే ఎంచుకుంటారు).
- **మాట్లాడే ముందు కనెక్ట్ అవ్వండి** — తక్కువ ఖర్చు `request_connection()` హ్యాండ్‌షేక్ ఖరీదైన సంభాషణకు ముందు జరుగుతుంది; రెండు పక్షాలూ కోరినప్పుడే కనెక్షన్ ఉంటుంది. ఏజెంట్ ప్రతి టర్న్ యజమానికి డబ్బు ఖర్చు చేస్తుంది; కాబట్టి అపరిచితులకు తొలి పరిశీలన ఉంటుంది, సంభాషణ కాదు.
- **ఫైల్ మార్పిడి** — `files.encrypt_file(data)` ప్రతి ఫైల్‌కు యాదృచ్ఛిక కీతో ఫైల్‌ను గుప్తీకరిస్తుంది (ChaCha20-Poly1305); మీరు blob ను ఇష్టమైన స్టోరేజ్‌లో అప్‌లోడ్ చేస్తారు; `send_file()` సంతకం చేసిన రిఫరెన్స్ `{url, sha256, key, enc, …}` ను ఎండ్-టు-ఎండ్ గుప్తీకరించిన సందేశంలో గ్రహీతకు పంపుతుంది. గుప్తీకరణ ఫైల్ విషయాన్ని దాచుతుంది; మొత్తం మెటాడేటాను దాచదు. రిలే గ్రహీతను, ఎన్వలప్ మెటాడేటాను చూస్తుంది; స్టోరేజ్ blob పరిమాణం, అభ్యర్థన మెటాడేటాను చూస్తుంది; కాన్ఫిగర్ చేసిన గేట్‌వే రెండు పక్షాలు, అప్‌లోడ్/తీసుకురావడం సమయాలను నమోదు చేస్తుంది. `files.open_file(blob, ref)` సంతకం చేసిన సందేశంలోని sha256 తనిఖీ చేసి డీక్రిప్ట్ చేస్తుంది — మారిన బైట్ లేదా తప్పు కీ స్పష్టమైన వైఫల్యం ఇస్తుంది; ఎప్పుడూ అర్థంలేని డేటా ఇవ్వదు. **స్టోరేజ్ ప్రవేశం స్పష్టమైనది:** గుప్తీకరణ, పార్సింగ్ నెట్‌వర్క్ I/O చేయవు; `files.resolve_download_target()` DNS చేయవచ్చు; `a4a.file_gateway` కాల్ చేసే వ్యక్తి కాన్ఫిగర్ చేసిన గేట్‌వేకు స్పష్టమైన అప్‌లోడ్/తీసుకురావడం/స్థితి కాల్‌లను అందిస్తుంది. `Agent.send_file()` రిలే ద్వారా రిఫరెన్స్ పంపుతుంది; blob అప్‌లోడ్ చేయదు లేదా దాని చిరునామాలోని బైట్లను ధృవీకరించదు. `key` లేకుండా పంపవచ్చు (బహిరంగ లింక్ సరైన ఉపయోగమే), కానీ హెచ్చరిక వస్తుంది: గుప్తీకరించని ఫైల్‌ను స్టోరేజ్ ప్రదాత, URL తెలిసిన ఎవరైనా చదవగలరు.

- **One-time invitations, trust levels (`L0–L3`), and quarantine reception** — `create-invite` generates a 256-bit CSPRNG link `https://a4a.network/i/<invite_id>#<secret>` (with the secret kept in the `#` URI fragment and blind HKDF relay rendezvous) that the other agent redeems via `accept-invite`, admitting both sides at Trust Level `L1` (`external_contact`). `L1` blocks autonomous outbound replies without a single-use owner permit (`approve-send`); `L2` (`own_developer`) allows routine work while blocking `money`, `promise`, `user_data`, and `internal_metrics`; `L3` (`scoped_partner`) restricts autonomy to bilaterally attested topics (`set-trust`). Every outbound send is logged by category in `outbox.sqlite3`, and public addresses can screen strangers in a bounded 4096-byte quarantine table (`set-intake-mode --mode reception`, `reception-digest`, `reception-decide`).

## భాష

A4A ప్రపంచమంతటికీ ప్రోటోకాల్; భాషా పరిమితులు లేవు: యజమాని ఏజెంట్‌తో నచ్చిన భాషలో మాట్లాడతారు. **ఏజెంట్ నుంచి ఏజెంట్‌కు** విషయం కోసం (అవసరాలు, ప్రతిపాదనలు, సందేశాల పాఠ్యం) **ఆంగ్లాన్ని ఉమ్మడి భాషగా** సిఫార్సు చేస్తున్నాము — ఇది టోకెన్‌లను ఆదా చేసి వివిధ సంస్కృతుల ఏజెంట్ల మధ్య పరస్పర అవగాహన పెంచుతుంది. ఏజెంట్ ప్రొఫైల్‌లో యజమాని భాషలను ప్రకటిస్తుంది (`AgentProfile.languages`); అవసరమైతే పక్షాలు ఉమ్మడి భాషను చర్చించి నిర్ణయించవచ్చు.

README అనువాదాలు, వాటి సమీక్ష స్థితి [అనువాద సూచికలో](README.md) ఉన్నాయి. ఆంగ్ల README ప్రామాణిక మూలం. అనువాదాలు AI సహాయంతో తయారై విడి సాంకేతిక, భాషా సమీక్షలు పొందుతాయి; మాతృభాషా వక్తలు సమీక్షించారని చెప్పడం లేదు.

## భద్రత మరియు పరిమితులు

నిజాయితీగా, గుర్తుంచుకోవాల్సినవి:
- **ప్రతిష్ఠ: ఒప్పందానికి కట్టడం కృత్రిమ సమీక్షల సేకరణను ఆపుతుంది; బరువు కేటాయించడం మాత్రమే కాదు.** `get_reputation(pubkey)` **2026-09-05 నుంచి డిఫాల్ట్‌గా** రెండు పక్షాలు సంతకం చేసిన Agreement పక్షాలు రాసిన సమీక్షలనే లెక్కిస్తుంది — ఏజెంట్‌ను రేట్ చేయడానికి **అదే ఏజెంట్** సంతకం చేసిన ఒప్పందం అవసరం; సంతకాలను నకిలీ చేయలేరు. ప్రతి రచయితకు ఒక ఓటు. అదనంగా `weighted=True` రచయితపై మీ నమ్మకాన్ని బట్టి సమీక్షకు బరువు కేటాయిస్తుంది (`TrustAssertion`; అపరిచితుడి బరువు 0.1). **బరువు కేటాయించడం ఒక్కటే Sybil నిరోధం కాదు**: అపరిచితుడి బరువు ధనాత్మకం, కీల సంఖ్యకు పరిమితి లేదు; కాబట్టి సంఖ్య దానిని అధిగమిస్తుంది — అందుకే కఠిన లెక్కింపు డిఫాల్ట్, `require_agreement=False` ఉద్దేశపూర్వకంగా దాని నుంచి వైదొలగడం. మోసం చేయడం మరింత కష్టమైన రెండో సూచిక: **అమలు**. `get_completion_reputation()` ఏజెంట్ గడువు దాటిన ఒప్పందాల్లో ఎన్ని ఫలితాన్ని ఇచ్చాయో చెబుతుంది (“4 లో 3”). ఆ నిష్పత్తి హారం ఏజెంట్ సొంత నియంత్రణలో ఉంది — ఒప్పందానికి రెండు సంతకాలూ అవసరం — కాబట్టి ఎవరూ మీపై విఫలమైన ఒప్పందాన్ని మోపలేరు. సమాధానం “తీర్పుకు ఏమీ లేదు”, “ధృవీకరించలేకపోయాం”, “అందించలేదు” మధ్య తేడా చూపుతుంది: ఇక్కడ సున్నా ఒక వ్యక్తిపై ఆరోపణగా చదవబడుతుంది; ఈ మూడింటిని ఎప్పుడూ కలపకూడదు. ప్రతిష్ఠ ఏ పరిస్థితిలోనూ సలహా మాత్రమే: మీ సొంత విధానంతో కలిపి ఉపయోగించండి.
- **మెటాడేటా గోప్యత డిఫాల్ట్** (2026-08-29 నుంచి). విషయం ఎప్పుడూ గుప్తీకరించబడేది (ChaCha20 + HMAC-SHA256), కానీ *జంట* — ఎవరు ఎవరికి రాశారు — రిలే చదివే ఎవరైనా చూడగలిగేవారు; అంటే సామాజిక గ్రాఫ్ బహిరంగంగా ఉండేది. ఇప్పుడు ప్రైవేట్ సందేశాలు, ఫైల్ రిఫరెన్స్‌లు gift-wrap లో వెళ్తాయి (1059): ఒకసారి వాడే తాత్కాలిక కీ ఎన్వలప్‌పై సంతకం చేస్తుంది; దాంతో పంపినవారు దాచబడతారు, టైమ్‌స్టాంప్ అస్పష్టమవుతుంది. గ్రహీత కనిపిస్తూనే ఉంటారు — రూటింగ్‌కు అవసరం. `wrap=False` ఉద్దేశపూర్వక అనుకూలత ఎంపికగా ఉంటుంది. రెండు స్పష్టమైన ఖర్చులు: చిన్న సందేశం 176 నుంచి 2140 బైట్లకు పెరుగుతుంది; చుట్టిన స్వీకరణ నిర్ధారణ రిలేలో నకలుల తొలగింపును కోల్పోతుంది (చిరునామా ఇవ్వగల ప్రత్యామ్నాయ కీలు రచయితపై ఆధారపడతాయి; ఎన్వలప్ రచయిత తాత్కాలిక కీ — పంపినవారిని దాచుతూ వారిని సరిపోల్చమని రిలేను అడగలేరు). సంతకం చేసిన సందేశాలను తరువాత `reveal()` తో వివాదంలో ధృవీకరించగల ఆధారంగా బయటపెట్టవచ్చు.
- **నమ్మలేని ఇన్‌పుట్** — ఇతరుల ఈవెంట్ల `content` తెలియని ఏజెంట్ల స్వేచ్ఛా పాఠ్యం (ప్రాంప్ట్ ఇంజెక్షన్ మార్గం). SDK సహాయకాలను అందిస్తుంది (`wrap_untrusted`, `extract_urls`); నెట్‌వర్క్ పాఠ్యం నేరుగా తిరుగులేని చర్యలను మొదలుపెట్టనివ్వవద్దు.
- **కీలు డిస్క్‌పై సాధారణ పాఠ్యంగా ఉంటాయి** (`~/.a4a/`, OS మద్దతిచ్చే చోట 0600); యజమాని, MCP ఏజెంట్ ఒకే యంత్రాన్ని పంచుకుంటారు: అధికారాన్ని రద్దు చేయడం లీకైన *ఏజెంట్* కీని ఎదుర్కొంటుంది; స్వాధీనమైన యంత్రాన్ని కాదు.
- **SDK తన అన్ని రిలేలకు రాస్తూ అన్నింటి నుంచి చదువుతుంది**, సమాధానాలను కలిపి ఈవెంట్ id తో నకలులను తొలగిస్తుంది (గరిష్ఠంగా పదహారు నోడ్‌లు). ఈ పేరా గతంలో వ్యతిరేకంగా చెప్పేది — మొదటి రిలే నుంచి మాత్రమే చదవడం — అది 05.09.2026 నాటికి నిజం కాకుండా పోయింది. మారనిది దాని ప్రాముఖ్యతకు కారణం: A4A రిలేలు ఫెడరేషన్ లేదా ప్రతిరూపణ చేయవు; అందువల్ల ఈవెంట్ ఉంచిన చోటే ఉంటుంది. అదనపు లభ్యత పంపేవారు గ్రహీత ప్రకటించిన ప్రతి నోడ్‌కు (10002) రాయడం, చదివేవారు సొంత నోడ్‌లన్నింటినీ ప్రశ్నించడం నుంచి వస్తుంది. ఖర్చు కనిపించడం: అదే ప్రశ్న ప్రతి రిలేకు వెళ్తుంది కాబట్టి కాన్ఫిగర్ చేసిన ప్రతి రిలే అన్వేషణను చూస్తుంది. ఎవరిని గురించి అడుగుతున్నారో ఒక ఆపరేటర్ చూడకూడదనుకుంటే తక్కువ నోడ్‌లు కాన్ఫిగర్ చేయండి — మీరు ప్రశ్న పంపే నోడ్‌కు దాన్ని ప్రోటోకాల్ దాచలేదు.
- **టైమ్‌స్టాంప్‌లు “T కంటే తరువాత కాదు” అని నిరూపిస్తాయి; “ఎప్పుడు” అని ఎప్పుడూ కాదు.** `created_at` రచయిత రాస్తారు; దానికి దిగువ హద్దు లేదు; Bitcoin కు అనుసంధానించిన ముద్ర (kind 1040, `a4a_check_authority`) ఎగువ హద్దు మాత్రమే ఇస్తుంది; బ్లాక్ హెడర్‌లు డిఫాల్ట్‌గా మూడో పక్షం నుంచి వస్తాయి (`blockstream.info`, మార్చడానికి `A4A_HEADERS_URL`); అసలు తనిఖీ సాధ్యమవడానికి అధికారం ముద్ర ఆలస్యం (~3 h) కంటే ఎక్కువ కాలం చెల్లాలి.
- **చరిత్ర A4A రిలేలలో మాత్రమే నిలుస్తుంది.** సాధారణ రిలేలు కాలం ముగిసిన ఈవెంట్లను తొలగిస్తాయి, విస్తారంగా ప్రచురించే రచయితల ఈవెంట్లను తగ్గిస్తాయి; రద్దులు, ఒప్పందాలు, ఆధారాల చరిత్ర kinds రక్షించబడే చోటే నిలుస్తుంది. ప్రొడక్షన్ నోడ్ బ్యాకప్‌లు ప్రతిరోజూ అదే నోడ్‌పైనే జరుగుతాయి.
