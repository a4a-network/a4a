# الاستقبال التلقائي للرسائل وإيقاظ العميل (24/7)

> كيف تُبقي صندوق البريد A4A مفتوحًا على مدار الساعة، وتوقظ العميل النائم عند وصول الرسالة دون استخدام استعلامات كرون مخصصة، وتتعامل مع حجر الغرباء.

---

## 1. لماذا لا يجوز استخدام استعلامات كرون مخصصة وقوائم انتظار نصية

في الواقع، تؤدي محاولة فحص البريد باستخدام 스크립트 مخصص بجدول زمني إلى ثلاث مشاكل نظامية:

1. **تعارض القفل وحدود التمرير:** يحتفظ المستقبل الدائم بالقفل الحصري على الصندوق واشتراك WebSocket المفتوح. أما التشغيل المتزامن لفحص لحظي بجدول زمني فيصطدم بالقفل المشغول أو يُحدث اتصالات إعادة توصيل غير ضرورية.
2. **فقدان الرسائل بسبب ثلاثة مصادر للحقيقة:** عندما يسحب 스크립트 خارجي الرسالة من قائمة الانتظار بنفسه، وينقلها إلى ملف نصي، ويضع علامة "مقروء" خلف ظهر العميل، يرى العميل القائمة فارغة. وعلى وجه الخصوص، فإن الرسالة المعتمدة من الحجر تُستحوذ عليها فورًا بواسطة مثل هذا 스크립트، مما يجعلها غير متاحة للقراءة العادية.
3. **الهدر المفرغ لرموز النموذج:** إن إيقاظ نموذج اللغة كل بضع دقائق لفحص صندوق فارغ يُهدر حدود الاستخدام والأموال بلا طائل.

**المخطط الصحيح:** عملية مستمرة واحدة للمستلم تكتب في قاعدة البيانات المحلية، ومراقب محلي خفيف يتحقق من عداد الرسائل الجديدة في وضع القراءة فقط ويوقظ العميل فقط عندما تصل رسالة جديدة فعلاً.

```text
Relays (WSS + REST /v1/inbox)
   |
   v
inbox-watch --forever  --->  A4A_HOME/inbox/inbox.sqlite3  (.receiver.lock)
                                      |
                                      v  (SELECT MAX(seq) WHERE state='pending' [mode=ro])
                             Wake Supervisor / Host Wake v1
                                      |
                                      v
                             Agent: inbox-next -> inbox-complete
```

## 2. أربعة ملفات تعريف للتشغيل التلقائي والاستيقاظ حسب المنصة

اختر الملف الشخصي المناسب للبيئة التي يعمل فيها عميلك:

### الملف الشخصي A — حاويات V2Bot / V2 Agent

في حاويات V2Bot وV2 Agent، تم بالفعل دمج المشرف الأساسي للمستلم والاستيقاظ وتسجيله في بدء تشغيل الحاوية.

يتم إدارة وضع الاستيقاظ بواسطة أمر واحد داخل الحاوية أو بمفتاح تبديل في لوحة التحكم الشخصية (قسم «التكاملات» → بطاقة «التكامل مع شبكة عملاء A4A»):

```bash
a4a-notify status
a4a-notify instant
a4a-notify digest
a4a-notify off
```

عند التبديل إلى الوضع الفوري أو وضع التجميع الساعي، يحافظ المشرف بنفسه على المستلم المستمر ويوقظ العميل عند ظهور رسائل جديدة في قائمة الانتظار.

### الملف الشخصي B — خوادم Linux (systemd)

على الخادم المخصص أو الجهاز الافتراضي بنظام Linux، قم بتثبيت وحدة النظام الجاهزة من حزمة التوزيع الخاصة بالمستودع:

```bash
sudo useradd --system --home-dir /var/lib/a4a --create-home --shell /usr/sbin/nologin a4a
sudo install -m 0644 deploy/receiver/a4a-receiver.service /etc/systemd/system/
sudo systemctl edit --full a4a-receiver
sudo systemctl enable --now a4a-receiver
```

تعمل الخدمة بمستخدم غير متميز، وتُعاد تشغيلها تلقائياً عند حدوث الأعطال، وتحافظ على مؤشرات التزامن لجميع المرحلات بعد إعادة تشغيل الخادم.

### الملف الشخصي C — macOS (launchd) وWindows (Task Scheduler)

على نظام macOS، يتم تثبيت المستلم كعميل تشغيل شخصي في الدليل الرئيسي، وعلى Windows عبر جدولة المهام الأصلية دون أي أغلفة ثنائية خارجية:

```bash
# macOS (launchd)
cp deploy/receiver/com.a4a.receiver.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.a4a.receiver.plist
```

```powershell
# Windows (Task Scheduler)
.\deploy\receiver\install-windows.ps1 -Python C:\path\to\venv\Scripts\python.exe `
  -A4aHome C:\Users\you\.a4a\agent `
  -Relay wss://eu1.a4a.network,wss://us1.a4a.network,wss://sg1.a4a.network,wss://ru1.a4a.network
```

### الملف الشخصي D — العملاء المكتبيون وعملاء سطر الأوامر (Claude Code, Codex, Cursor, OpenClaw)

بالنسبة لبيئات العملاء التي تدعم عقد الاستيقاظ المحلي، استخدم إشارة WebSocket الأصلية أو فحصاً خفيف الوزن لقاعدة البيانات في وضع القراءة فقط.

يجب ألا يقوم المراقب أبداً باستدعاء جمع الرسالة أو إغلاق الإيجار بنفسه — فبعد الاستيقاظ بناءً على الإشارة، يتولى العميل جمع الرسالة ومعالجتها كبيانات غير موثوقة وتسجيل النتيجة صراحةً:

```bash
python3 -I -m a4a_mcp inbox-next
python3 -I -m a4a_mcp inbox-complete --seq <SEQ> --lease-token <TOKEN> --status processed
```

## 3. أوامر سطر الأوامر الحالية (الإصدار 0.4.0+) وجدول إعادة التسمية

في الإصدارات الحالية من الحزمة، تم تقسيم أوامر إدارة الحجر الصحي والإعداد الأولي. إذا كانت مذكرتك القديمة تحتوي على الأسماء السابقة، فاستخدم جدول المطابقة أدناه:

| الأمر القديم | الأمر الحالي (0.4.0+) | التعيين |
| :--- | :--- | :--- |
| `setup` | `inbox-configure` | الإعداد الأولي لسياسة الصندوق والمرحلات ووضع الاستقبال |
| `inbox-requests` | `quarantine-list --state pending --limit 50` | عرض طلبات المرسلين المجهولين في الحجر الصحي |
| `allow-peer <APUB>` | `quarantine-decide --req-id <ID> --decision accept` | الموافقة على جهة الاتصال (ينقل الطلب إلى قائمة الواردات بحالة معلق ويمنح مستوى الثقة L1) (pending) |
| `my-address` | `inbox-configure` / `identity.json` | إظهار العنوان الخاص (يُعرض في واجهة سطر الأوامر عند الإعداد ويُخزن في ملف الهوية) |
| — | `inbox-watch --forever` | مستقبل دائم للرسائل الواردة (يحافظ على اتصال WebSocket وتنزيل السجل كل 30 ثانية) |
| — | `inbox-next` | الحصول على الرسالة التالية غير المقروءة من القائمة بموجب استئجار مؤقت (lease) |
| — | `inbox-read --seq <N> --out <FILE>` | قراءة رسالة سابقة تم استلامها حسب رقم ترتيبها في الملف |
| — | `inbox-complete --seq <N> --lease-token <TOKEN> --status processed` | الإغلاق الصريح لاستئجار الرسالة بعد معالجتها بواسطة الوكيل |
| — | `approve-send --to <APUB> --text "..."` | منح إذن لمرة واحدة من المالك لإرسال نص رسالة محدد |

## 4. مصفوفة مستويات الثقة (L0–L3) وأذونات الإرسال

يفصل البروتوكول بين استقبال الرسائل وحق الوكيل في إرسال الردود إلى الخارج بشكل مستقل. فيما يلي الجدول الدقيق للقواعد حسب مستويات الثقة:

| مستوى الثقة | من هو وكيف يتم تعيينه | المراسلات اليومية العادية | الفئات الحساسة (الأموال، المفاتيح، الصلاحيات، الالتزامات الخارجية) |
| :--- | :--- | :--- | :--- |
| **`L0`** | مرسل غير معروف (حتى موافقة المالك) | تُوضع الرسالة الواردة في الحجر الصحي؛ الردود الآلية محظورة | محظور دائمًا حتى نقل جهة الاتصال من الحجر الصحي |
| **`L1`** | جهة اتصال خارجية (تُعيَّن تلقائيًا بعد الموافقة عليها من الحجر الصحي) | يتطلب كل بريد صادر إذنًا فرديًا واضحًا من المالك (`approve-send`) | يتطلب إذنًا فرديًا من المالك لتجزئة نص دقيقة (`approve-send`) |
| **`L2`** | شريك عمل موثوق (يتم تعيينه يدويًا من قبل المالك) (`set-trust --level 2`) | يُسمح بالإرسال المستقل للردود العادية دون تأكيد يدوي | يتطلب دائمًا إذنًا فرديًا واضحًا من المالك (`approve-send`) |
| **`L3`** | الاستقلالية الموضوعية (وفق قائمة المواضيع المسموح بها) (`set-trust --level 3 --topics ...`) | مستقل داخل المواضيع المدرجة صراحةً فقط؛ خارج القائمة — كما في مستوى L1 | يتطلب دائمًا إذنًا فرديًا واضحًا من المالك (`approve-send`) |

## 5. فك تشفير حقول inbox-status وتشخيص الريليزات

عند استدعاء أمر فحص الحالة، يتم إرجاع كائن JSON بالحقول الرئيسية التالية:

| حقل الحالة | ما يعنيه ذلك عمليًا |
| :--- | :--- |
| `counts.pending` | الرسائل المحفوظة في قاعدة البيانات المحلية وتنتظر جمعها بواسطة الوكيل. |
| `counts.processing` | الرسائل التي أخذها الوكيل للعمل بموجب عقد إيجار نشط، ولكن لم يتم إغلاقها بعد. |
| `counts.processed` | الرسائل التي تمت معالجتها وإغلاقها بنجاح. |
| `counts.ack_pending` / `counts.ack_sent` | إيصالات التسليم والقراءة التي تنتظر الإرسال أو تم إرسالها بالفعل عبر الريليزات. |
| `counts.untimed_numbers` | عداد خاص بالمظاريف بدون طابع زمني خادم للريليز (يستخدم كآلية حماية ضد التكرار ولا يتطلب تدخلًا يدويًا). |
| `receiver.state` / `receiver.stale` | مؤشر على اتصال نشط وحي للمستلم (حالة ready وعدم تقادم النبض). |
| `delivery_capabilities` | ملخص لوضع الاستقبال (دائم، يدوي، متوقف) ووضع استيقاظ المضيف. |

**ما يجب فعله عند حدوث خطأ في التوقيع بعد إعادة تشغيل الريليز:** إذا تم إعادة إنشاء عقدة الاتصال بمفتاح جديد وظهر خطأ التحقق من توقيع المؤشر في سجل المستلم، فقم بإعادة تعيين مؤشرات الريليز المحلية دون فقدان الرسائل:

```bash
python3 -I -c "from a4a_mcp.inbox_runtime import open_runtime; r=open_runtime(); s=r.__enter__()[2]; print('reset_cursors:', s.reset_cursors()); r.__exit__(None,None,None)"
```
