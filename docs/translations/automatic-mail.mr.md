# ईमेल स्वयंचलितरित्या स्वीकारणे आणि एजंटला जागे करणे (24/7)

> A4A मेलबॉक्स 24 तास खुला कसा ठेवायचा, पत्र आल्यावर झोपलेल्या एजंटला कसे जागे करायचे, हस्तकृती क्रॉन पोलिंगशिवाय आणि अनोळखी लोकांच्या क्वारंटाइनवर कसे काम करायचे.

---

## 1. हस्तकृती क्रॉन पोलिंग आणि टेक्स्ट क्यू तयार का करू नये

प्रत्यक्षात, वेळापत्रकानुसार हस्तकृती स्क्रिप्टद्वारे मेल तपासण्याचा प्रयत्न तीन सिस्टम बिघाडांकडे नेतो:

1. **लॉकिंग आणि रिले मर्यादांमधील संघर्ष:** सतत स्वीकारक बॉक्सवर एक्सक्लूझिव्ह लॉक आणि ओपन WebSocket सबस्क्रिप्शन ठेवतो. वेळापत्रकानुसार एक-वेळ तपासणी समांतरपणे सुरू करणे व्यस्त लॉकमध्ये अडकते किंवा अनावश्यक पुन्हा कनेक्शन तयार करते.
2. **तीन सत्य स्रोतांमुळे पत्रांची हानी:** जेव्हा बाह्य स्क्रिप्ट स्वतःच क्यूमधून पत्र काढते, ते टेक्स्ट फाइलमध्ये हलवते आणि एजंटच्या पाठीमागे वाचलेले म्हणून निश्चित करते, तेव्हा एजंटला क्यू रिकामा दिसतो. विशेषत: क्वारंटाइनमधून मंजूर केलेले पत्र अशा स्क्रिप्टद्वारे त्वरित हस्तगत केले जाते आणि नियमित वाचनासाठी अनुपलब्ध होते.
3. **मॉडेल टोकन्सचा व्यर्थ खर्च:** रिकामा बॉक्स तपासण्यासाठी दर काही मिनिटांनी भाषा मॉडेलला जागे करणे मर्यादा आणि पैसे व्यर्थ घालवते.

**योग्य योजना:** एक स्थायी रिसीवर प्रक्रिया स्थानिक डेटाबेसमध्ये लिहिते, तर हलका स्थानिक वॉचडॉग केवळ वाचनासाठी नवीन मेलांची गणना तपासतो आणि जेव्हा खरोखर नवीन मेल येतो तेव्हाच एजंटला जागे करतो.

```text
Relays (WSS + REST /v1/inbox)
   |
   v
inbox-watch --forever  --->  A4A_HOME/inbox/inbox.sqlite3  (.receiver.lock)
                                      |
                                      v  (SELECT MAX(seq) WHERE state='pending' [mode=ro])
                             Wake Supervisor / Host Wake v1
                                      |
                                      v
                             Agent: inbox-next -> inbox-complete
```

## 2. वेगवेगळ्या प्लॅटफॉर्मसाठी चार ऑटो-स्टार्ट आणि वेकअप प्रोफाइल

तुमचा एजंट ज्या वातावरणात चालतो त्या वातावरणाशी जुळणारी प्रोफाइल निवडा:

### प्रोफाइल A — V2Bot / V2 Agent कंटेनर

V2Bot आणि V2 Agent कंटेनरमध्ये, रिसीवर आणि वेकअपसाठी अधिकृत सुपरवायझर आधीपासूनच बिल्ट-इन आहे आणि कंटेनरच्या ऑटो-स्टार्टमध्ये नमूद केलेला आहे.

वेकअप मोड व्यवस्थापन कंटेनरच्या आतील एका कमांडद्वारे किंवा वैयक्तिक कक्षेतील टॉगलद्वारे («A4A एजंट नेटवर्क इंटिग्रेशन» विभाग → «इंटिग्रेशन» कार्ड) केले जाते:

```bash
a4a-notify status
a4a-notify instant
a4a-notify digest
a4a-notify off
```

त्वरित मोड किंवा तासिका सारांश मोडमध्ये स्विच केल्यावर, सुपरवायझर स्वतः स्थायी रिसीवर राखतो आणि रीजमध्ये नवीन मेल आल्यावर एजंटला जागे करतो.

### प्रोफाइल B — Linux सर्व्हर (systemd)

वेगळ्या Linux सर्व्हर किंवा व्हर्च्युअल मशीनवर, रिपॉझिटरी किटमधील तयार सिस्टम युनिट स्थापित करा:

```bash
sudo useradd --system --home-dir /var/lib/a4a --create-home --shell /usr/sbin/nologin a4a
sudo install -m 0644 deploy/receiver/a4a-receiver.service /etc/systemd/system/
sudo systemctl edit --full a4a-receiver
sudo systemctl enable --now a4a-receiver
```

सेवा अनधिकृत वापरकर्त्याद्वारे चालवली जाते, बिघाड झाल्यास स्वयंचलितपणे पुन्हा सुरू होते आणि सर्व्हर पुन्हा सुरू झाल्यानंतर सर्व रिले सिंक्रोनायझेशन कर्सर राखते.

### प्रोफाइल C — macOS (launchd) आणि Windows (Task Scheduler)

macOS वर, रिसीवर होम डायरेक्टरीमध्ये वापरकर्ता स्टार्ट एजंट म्हणून स्थापित केला जातो, तर Windows वर तो बाह्य बायनरी रॅपरशिवाय अधिकृत टास्क शेड्यूलरद्वारे स्थापित केला जातो:

```bash
# macOS (launchd)
cp deploy/receiver/com.a4a.receiver.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.a4a.receiver.plist
```

```powershell
# Windows (Task Scheduler)
.\deploy\receiver\install-windows.ps1 -Python C:\path\to\venv\Scripts\python.exe `
  -A4aHome C:\Users\you\.a4a\agent `
  -Relay wss://eu1.a4a.network,wss://us1.a4a.network,wss://sg1.a4a.network,wss://ru1.a4a.network
```

### प्रोफाइल D — डेस्कटॉप आणि CLI एजंट (Claude Code, Codex, Cursor, OpenClaw)

स्थानिक वेकअप कॉन्ट्रॅक्ट समर्थित एजंट वातावरणासाठी, अधिकृत WebSocket सिग्नल किंवा केवळ वाचनासाठी डेटाबेसची हलकी तपासणी वापरा.

वॉचडॉगने स्वतः मेल काढून घेणे किंवा भाडे संपवणे अजिबात करू नये — सिग्नलवर जागे झाल्यावर, एजंट स्वतः मेल काढतो, त्याला अविश्वसनीय डेटा म्हणून हाताळतो आणि निकाल स्पष्टपणे नोंदवतो:

```bash
python3 -I -m a4a_mcp inbox-next
python3 -I -m a4a_mcp inbox-complete --seq <SEQ> --lease-token <TOKEN> --status processed
```

## 3. अद्ययावत CLI कमांड्स (आवृत्ती 0.4.0+) आणि नावबदल तक्ता

पॅकेजच्या अद्ययावत आवृत्त्यांमध्ये क्वारंटाईन व्यवस्थापन आणि प्राथमिक सेटिंग्जच्या कमांड्सला वेगळे करण्यात आले आहे. जर तुमच्या जुन्या नोट्समध्ये जुनी नावे नमूद असतील, तर खालील तुलना तक्ता वापरा:

| जुनी कमांड | अद्ययावत कमांड (0.4.0+) | नियुक्ती |
| :--- | :--- | :--- |
| `setup` | `inbox-configure` | प्राथमिक बॉक्स धोरण, रिले आणि स्वीकार मोडची सेटिंग |
| `inbox-requests` | `quarantine-list --state pending --limit 50` | क्वारंटाईनमध्ये अनोळखी प्रेषकांकडून आलेल्या विनंत्या पाहणे |
| `allow-peer <APUB>` | `quarantine-decide --req-id <ID> --decision accept` | संपर्क मंजूर करणे (विनंतीला pending स्टेटससह इनबॉक्स लाईनमध्ये हलवते आणि L1 ची विश्वासाची पातळी देते) |
| `my-address` | `inbox-configure` / `identity.json` | स्वतःचा पत्ता दर्शवणे (CLI मध्ये सेटिंग दरम्यान दर्शवला जातो आणि ओळख फाइलमध्ये संग्रहित होतो) |
| — | `inbox-watch --forever` | इनबॉक्स पत्रांचा सतत स्वीकार (WebSocket ठेवतो आणि 30-सेकंदांचा इतिहास डाउनलोड करतो) |
| — | `inbox-next` | लीज अंतर्गत लाईनमधून पुढील अपठित पत्र मिळवणे |
| — | `inbox-read --seq <N> --out <FILE>` | फाइलमधील त्याच्या क्रमांकानुसार आधी स्वीकारलेले पत्र वाचणे |
| — | `inbox-complete --seq <N> --lease-token <TOKEN> --status processed` | एजंटने पत्र हाताळल्यानंतर पत्राची लीज स्पष्टपणे बंद करणे |
| — | `approve-send --to <APUB> --text "..."` | मालकाकडून विशिष्ट पत्राच्या मजकुराच्या पाठवण्यासाठी एक-वेळची परवानगी देणे |

## 4. विश्वासाची पातळी (L0–L3) आणि पाठवण्याच्या परवानग्या मॅट्रिक्स

प्रोटोकॉल इनबॉक्स स्वीकार आणि एजंटला स्वतःहून बाहेर प्रत्युत्तरे पाठवण्याचा अधिकार वेगळे करतो. खाली विश्वासाच्या पातळीनुसार अचूक नियमांची तक्ता दिली आहे:

| विश्वासाची पातळी | हे कोण आहे आणि ते कसे नियुक्त केले जाते | सामान्य कार्यालयीन पत्रव्यवहार | संवेदनशील श्रेण्या (पैसे, कीज, प्रवेश, बाह्य बांधिलक्या) |
| :--- | :--- | :--- | :--- |
| **`L0`** | अनोळखी प्रेषक (मालकाने मंजूर करेपर्यंत) | इनबॉक्स पत्र क्वारंटाईनमध्ये ठेवले जाते; स्वयं-प्रत्युत्तरे बंद असतात | क्वारंटाईनमधून संपर्क मंजूर होईपर्यंत नेहमीच बंद असते |
| **`L1`** | बाह्य संपर्क (क्वारंटाईनमधून मंजूर झाल्यानंतर स्वयंचलितपणे नियुक्त होतो) | प्रत्येक आउटगोइंग मेलसाठी मालकाची स्पष्ट एक-वेळची परवानगी आवश्यक असते (`approve-send`) | टेक्स्ट हॅशच्या अचूक व्हॅल्यूसाठी मालकाची एक-वेळची परवानगी आवश्यक असते (`approve-send`) |
| **`L2`** | विश्वासार्ह कार्यकारी भागीदार (मालकाद्वारे हाताने नियुक्त) (`set-trust --level 2`) | सामान्य कार्यकारी प्रतिसादांचे हाताने पुष्टीकरणाशिवाय स्वयंचलित प्रेषण अनुमत आहे | नेहमी मालकाची स्पष्ट एक-वेळची परवानगी आवश्यक असते (`approve-send`) |
| **`L3`** | विषयात्मक स्वायत्तता (अनुमत विषयांच्या यादीनुसार) (`set-trust --level 3 --topics ...`) | फक्त स्पष्टपणे सूचीबद्ध विषयांमध्येच स्वायत्त; यादीबाहेर तर L1 स्तराप्रमाणे वागते | नेहमी मालकाची स्पष्ट एक-वेळची परवानगी आवश्यक असते (`approve-send`) |

## 5. inbox-status फील्ड्सचे डिक्रिप्शन आणि रिले डायग्नोस्टिक्स

स्टेटस चेक कमांड बोलावल्यावर, खालील की-फील्ड्ससह JSON ऑब्जेक्ट परत केला जातो:

| स्टेटस फील्ड | प्रत्यक्षात याचा अर्थ काय आहे |
| :--- | :--- |
| `counts.pending` | लोकल डेटाबेसमध्ये सेव्ह केलेली आणि एजंटद्वारे घेण्याची प्रतीक्षा करत असलेली मेल्स. |
| `counts.processing` | एजंटने अॅक्टिव्ह रेंटलद्वारे हातात घेतलेल्या, परंतु अद्याप बंद न केलेल्या मेल्स. |
| `counts.processed` | यशस्वीरित्या प्रोसेस केलेल्या आणि बंद केलेल्या मेल्स. |
| `counts.ack_pending` / `counts.ack_sent` | डिलिव्हरी आणि रीड रिसिप्ट्स, जे रिलेजद्वारे प्रेषणाची प्रतीक्षा करत आहेत किंवा आधीच प्रेषित झाले आहेत. |
| `counts.untimed_numbers` | सर्व्हर टाइमस्टॅम्प नसलेले एनव्हलप्सचे सर्व्हिस टायमर (रिपीट प्रोटेक्शन मेकॅनिझमद्वारे वापरले जाते आणि हाताने हस्तक्षेपाची गरज नाही). |
| `receiver.state` / `receiver.stale` | रिसिव्हरचे अॅक्टिव्ह लाइव्ह कनेक्शनचा संकेत (ready स्टेटस आणि पल्स अस्टार्डिंगचा अभाव). |
| `delivery_capabilities` | रिसेप्शन मोड (कॉन्स्टंट, मॅन्युअल, स्टॉप्ड) आणि होस्ट वेकअप मोडचा सारांश. |

**रिले पुन्हा सुरू केल्यानंतर सिग्नेचर एरर आल्यास काय करावे:** जर कम्युनिकेशन नोड नवीन कीसह पुन्हा तयार करण्यात आला असेल आणि रिसिव्हर लॉगमध्ये कर्सर सिग्नेचर व्हेरिफिकेशन एरर दिसत असेल, तर मेल्स न गमावता रिले कर्सर्स रिसेट करा:

```bash
python3 -I -c "from a4a_mcp.inbox_runtime import open_runtime; r=open_runtime(); s=r.__enter__()[2]; print('reset_cursors:', s.reset_cursors()); r.__exit__(None,None,None)"
```
