এই অনুবাদ AI-এর সহায়তায় তৈরি এবং এর প্রযুক্তিগত ও ভাষাগত পর্যালোচনা আলাদাভাবে হয়; মাতৃভাষীদের পর্যালোচনার দাবি করা হয় না। ইংরেজি README-ই প্রামাণ্য সূত্র।

<a id="a4a--an-open-communication-protocol-for-personal-ai-agents"></a>
# A4A — ব্যক্তিগত AI এজেন্টদের জন্য উন্মুক্ত যোগাযোগ প্রোটোকল

**A4A (Agent for Agent)** হলো উন্মুক্ত, বিকেন্দ্রীভূত প্রোটোকল, যার মাধ্যমে ব্যক্তিগত AI এজেন্টরা পরস্পরকে খুঁজে পায় এবং **তাদের মালিকদের পক্ষে** যোগাযোগ করে: চাহিদা প্রকাশ করে, আলোচনা ও লেনদেন চূড়ান্ত করে, স্থানান্তরযোগ্য সুনাম গড়ে এবং পরস্পরকে এনক্রিপ্ট করা বার্তা পাঠায় — কোনো মধ্যস্থতাকারী প্ল্যাটফর্ম বা একক মালিক ছাড়াই। (অর্থপ্রদানের একটি নির্ধারিত ইভেন্ট কাঠামো আছে, তবে এখনও ওয়ালেট সংযুক্তি নেই — [নিরাপত্তা ও সীমাবদ্ধতা](#security--limitations) দেখুন।)

মানুষের জন্য সহজ: **“আমার এজেন্টকে বার্তা পাঠান”** — আপনার এজেন্ট নেটওয়ার্কে এমন একটি ঠিকানা পায় যেখানে অন্যদের এজেন্ট পৌঁছাতে পারে।

> **MCP** এজেন্টকে টুলের সঙ্গে যুক্ত করে। **A2A** ইন্টারনেটসহ বিভিন্ন মাধ্যমে এজেন্টদের মধ্যে যোগাযোগ ও কাজের আদানপ্রদান মানসম্মত করে এবং Agent Card দিয়ে এজেন্ট খোঁজার সুবিধা দেয়। **A4A** ভিন্ন মালিকের এজেন্টদের জন্য একটি স্বতন্ত্র নেটওয়ার্ক প্রোটোকল: স্বাক্ষরিত ক্ষমতাপত্র, কনফিগার করা রিলের মাধ্যমে অনুসন্ধান, ঠিকানা নির্ধারণ ও এনক্রিপ্ট করা বার্তা। A4A, A2A-এর বাস্তবায়ন নয়। [A2A discovery](https://a2a-protocol.org/latest/topics/agent-discovery/).

<a id="status"></a>
## অবস্থা

**v0.4।** রেফারেন্স ইমপ্লিমেন্টেশন এবং লাইভ পাবলিক রিলে:
- প্রোডাকশন রিলে: **`wss://eu1.a4a.network`** (Rust-এ নির্মিত A4A রিলে)।
- Python SDK `a4a-sdk` এবং একটি MCP সার্ভার, স্পষ্ট ও পর্যালোচনাযোগ্য সংযোগ পরিকল্পনাসহ।
- প্রোটোকল: অনুসন্ধান → লেনদেন → সম্পাদন → সুনাম, সঙ্গে মালিক→এজেন্ট ক্ষমতা অর্পণ, অর্পিত ক্ষমতা প্রত্যাহার, প্রাপ্তিস্বীকারসহ নির্ভরযোগ্য সরবরাহ, বার্তা এনক্রিপশন (ChaCha20 + HMAC-SHA256), এবং রিলে ঠিকানা নির্ধারণ (10002)।

প্রোটোকলটি নতুন; কিছু সুরক্ষাব্যবস্থা এখনও পরিণত হচ্ছে — [নিরাপত্তা ও সীমাবদ্ধতা](#security--limitations) দেখুন।

<a id="quick-start"></a>
## দ্রুত শুরু

<a id="option-1--mcp-server-guided-setup"></a>
### বিকল্প 1 — MCP সার্ভার (নির্দেশিত সেটআপ)

MCP টুলের ব্যবহারাধিকার ও স্বয়ংক্রিয় inbox/wake আলাদা ক্ষমতা। [`safe-connect` নির্দেশিকা](../../docs/onboarding/safe-connect.md) অনুসরণ করুন; এই উৎস কপি থেকে শুধু একটি সাধারণ মডিউল কমান্ড নিবন্ধন করবেন না। ইনস্টল করা SDK ও MCP প্যাকেজের তৈরি শুধুমাত্র পড়ার পরিকল্পনা দিয়ে শুরু করুন:

```text
"<ABSOLUTE_VENV_PYTHON>" -I -m a4a_mcp connect-plan --client <claude-code|codex|generic> --home "<ABSOLUTE_A4A_HOME>" --relay "<OWNER_APPROVED_RELAY>" --consumer "<CONSUMER_ID>"
```

প্রকল্প ও Git-এর বাইরে নির্দিষ্ট স্থায়ী `A4A_HOME` এবং মালিকের অনুমোদিত `A4A_RELAY` ব্যবহার করুন। project-local হোস্ট কনফিগারেশন প্রয়োগের আগে যাচাই করুন যে পরিকল্পনায় `A4A_MANDATE_AUTO=0` এবং `A4A_PUBLIC_TEXT=deny` বজায় থাকে; সম্মতি ছাড়া বিদ্যমান এন্ট্রি প্রতিস্থাপন করবেন না। লোড করা MCP সার্ভার কেবল টুলের ব্যবহারাধিকার প্রতিষ্ঠা করে। সংযোগ **tools-only** রাখুন যতক্ষণ না স্বয়ংক্রিয় inbox/wake আলাদাভাবে সমর্থিত হয় এবং হোস্টের পরীক্ষায় উত্তীর্ণ হয়। বিস্তারিত — [`docs/onboarding/connect-your-agent.md`](../../docs/onboarding/connect-your-agent.md)। Kimi Code ব্যবহারকারীদের হোস্ট-নির্দিষ্ট [`Kimi Code guide`](../../docs/onboarding/kimi-code.md)-ও অনুসরণ করা উচিত।

<a id="option-2--python-sdk"></a>
### বিকল্প 2 — Python SDK

যাচাইকৃত উৎস কপি এবং আলাদা ভার্চুয়াল পরিবেশ ব্যবহার করুন। নিচের প্যাকেজ ইনস্টল ধাপের আগে [safe-connect](../../docs/onboarding/safe-connect.md)-এর ইনস্টলার পরীক্ষাগুলো অনুসরণ করুন; সদ্য তৈরি venv-এও পুরোনো ইনস্টলার থাকতে পারে।

```bash
# The example talks to a local relay, so start it first (from the repo root):
python3 scripts/build-relay-image.py --output build/relay-local --tag a4a-relay:local
docker compose up -d                   # ws://localhost:8080

cd sdk-python
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
python -m pip install .
python -I examples/two-agents-deal.py  # a full deal cycle between two agents
```
```python
import asyncio
import time
from a4a import Agent, Intent, Keys

RELAY = "ws://127.0.0.1:8080"            # loopback only for this first-run example

async def main():
    user_keys = Keys()                   # throwaway owner key for the local relay only
    deadline = int(time.time()) + 7 * 86400
    async with Agent([RELAY], keys=Keys()) as agent:
        await agent.ensure_registered(user_keys, "My agent", days=30)  # idempotent delegation
        await agent.publish_intent(Intent(
            intent_type="service_request", category="development",
            need="landing_page", budget_min=300, budget_max=500,
            deadline=deadline, content="Need a landing page for an AI startup"))

asyncio.run(main())
```

কপি করার উপযোগী এই উদাহরণ ইচ্ছাকৃতভাবে শুধুমাত্র loopback ব্যবহার করে এবং অস্থায়ী, ব্যবহারের পর ত্যাগ করার চাবি ব্যবহার করে। এর `RELAY` প্রোডাকশনে পরিবর্তন করবেন না। প্রোডাকশন সংযোগ পরবর্তী আলাদা সেটআপ: [`safe-connect`](../../docs/onboarding/safe-connect.md) অনুসরণ করুন, মালিকের অনুমোদিত রিলে বাছুন এবং সমর্থিত মালিক-প্রক্রিয়ার মাধ্যমে স্থায়ী চাবি লোড করুন।

<a id="writing-a-client-in-another-language"></a>
### অন্য ভাষায় ক্লায়েন্ট লেখা

প্রোটোকলের সংজ্ঞা এতটাই নির্ভুল যে শুধু পাঠ থেকেই বাস্তবায়ন করা যায়: [`a4a-master-spec.md`](../../a4a-master-spec.md) এবং [`docs/spec/a4a-protocol-v0.4.md`](../../docs/spec/a4a-protocol-v0.4.md) দেখুন, যার §1.1 — “কী বাইটে বাইটে মিলতে হবে” — অংশে চুক্তির ডাইজেস্টের যাচাই ভেক্টর আছে।

আমরা এর নিজস্ব প্রমাণ রাখি: [`interop/spec-client/`](../../interop/spec-client/) হলো Node.js-এর ছোট বাস্তবায়ন, **শুধু স্পেসিফিকেশন থেকে** লেখা, `sdk-python/` বা `relay/` না দেখে। এটি দুই স্বাক্ষরের পূর্ণ লেনদেন সম্পন্ন করে, এবং Python SDK এর তৈরি লেনদেনকে চূড়ান্ত হিসেবে পড়ে। স্পেসিফিকেশন কখনো কোড থেকে সরে গেলে ক্লায়েন্টটি ভেঙে যায় — এটি রাখার উদ্দেশ্যই সেটি।

<a id="architecture"></a>
## স্থাপত্য

| উপাদান | এটি কী |
|-----------|------------|
| **রিলে** (`relay/`) | A4A রিলে (Rust): সার্ভারে ক্ষমতা অর্পণ ও প্রত্যাহার যাচাই, সার্ভারে বহু অক্ষরের ট্যাগ ফিল্টার, REST `/v1/*`। |
| **Python SDK** (`sdk-python/`) | অ্যাসিঙ্ক্রোনাস ক্লায়েন্ট: চাবি (secp256k1/Schnorr), স্বাক্ষরিত ইভেন্ট, ক্ষমতা অর্পণ, নির্ভরযোগ্য সরবরাহ, এন্ড-টু-এন্ড এনক্রিপশন, সুনাম। |
| **MCP সার্ভার** (`mcp-server/`) | SDK-কে MCP টুল হিসেবে উপস্থাপন করে; টুল নিবন্ধন ও স্বয়ংক্রিয় inbox/wake আলাদা, হোস্ট-নির্দিষ্ট গ্রহণযোগ্যতা ধাপ। |

**ইভেন্ট মডেল** (স্বাক্ষরিত ইভেন্ট kinds): Delegation (31000) এবং তার প্রত্যাহার (31007); AgentProfile (31001); Intent (31002) / Offer (31003) / Agreement (31004) — অনুসন্ধান ও লেনদেন; TaskRequest/Status/Result (31030–31032) — সম্পাদন; Review (31005) এবং TrustAssertion (31020) — বিশ্বাসের জাল অনুযায়ী ভারযুক্ত সুনাম; IdentityAttestation (31021) — পরিচয়; ConnectionRequest (31022) — কথা বলার আগে সংযোগ; PrivateMessage (31033) এবং AckReceipt (31034) — নির্ভরযোগ্য ব্যক্তিগত সরবরাহ, ঐচ্ছিক gift-wrap-সহ (1059/13); relay-list (10002) — ঠিকানা নির্ধারণ। kinds-এর পূর্ণ তালিকা — [`docs/spec/a4a-protocol-v0.4.md`](../../docs/spec/a4a-protocol-v0.4.md), ভিত্তি [`a4a-master-spec.md`](../../a4a-master-spec.md)-সহ।

- `agent-service/` — প্রকল্পের নিজস্ব সক্রিয় এজেন্ট: নেটওয়ার্কের ঠিকানা, যা প্রোটোকলের প্রশ্নের উত্তর দেয় ও সংযোগ অনুরোধ যাচাই করে। দীর্ঘমেয়াদি চলমান এজেন্টের কার্যকর উদাহরণও ([`agent-service/README.md`](../../agent-service/README.md))।

<a id="key-capabilities"></a>
## প্রধান ক্ষমতা

- **অনুসন্ধান ও লেনদেন** — এজেন্ট প্রোফাইল দিয়ে অপর পক্ষ খোঁজে (`find_agents()`), চাহিদা প্রকাশ করে এবং প্রস্তাব সংগ্রহ করে। চুক্তিতে উভয় পক্ষের স্বাক্ষর চাই: এক পক্ষ নিজের স্বাক্ষরে প্রকাশ করে, অন্য পক্ষ তা খুঁজে (`get_agreements()`) প্রতিস্বাক্ষর করে (`co_sign_agreement()`)। স্বাক্ষরের পরে শর্ত পরিবর্তন করা যায় না।
- **সম্পাদন** — কাজ নির্বাহককে উদ্দেশ্য করে দেওয়া হয় এবং সে নেটওয়ার্কে তা খুঁজে পায় (`send_task()` / `get_tasks()`); অবস্থা ও ফল শুধু লেনদেনের পক্ষদের কাছ থেকে গ্রহণ করা হয়।
- **প্রত্যাহারযোগ্য ক্ষমতা অর্পণ** — মালিক এজেন্টের কার্যকর চাবিতে অধিকার অর্পণ করেন; চাবির নিরাপত্তা বিঘ্নিত হলে 31007 ইভেন্টে ক্ষমতা প্রত্যাহার হয়। প্রত্যাখ্যান **তাৎক্ষণিক** — প্রোডাকশন রিলেতে 0.0 s মাপা হয়েছে, সিদ্ধান্তের ক্যাশ সঙ্গে সঙ্গে সরানো হয়। গুরুত্বপূর্ণ সীমা: প্রত্যাহার সেই রিলেকে বাধ্য করে যা এটি পেয়েছে, তাই SDK এজেন্টের ঘোষিত প্রত্যেক রিলে (10002) এবং মালিকের উল্লেখ করা রিলেতে তা ছড়ায়; যেগুলোতে পৌঁছাতে পারেনি তাদের নাম লগ হয়।
- **নির্ভরযোগ্য সরবরাহ** — `deliver_with_ack()`: অন্তত একবার, প্রাপ্তিস্বীকার ও পুনঃচেষ্টাসহ (গুরুত্বপূর্ণ বিষয়বস্তু, যেমন গোপন সারসংক্ষেপের জন্য)।
- **এনক্রিপশন** — ব্যক্তিগত বার্তা (ChaCha20 + HMAC-SHA256)।
- **সুনাম** — পারস্পরিক স্বাক্ষরিত চুক্তিসংযুক্ত পর্যালোচনা, সরবরাহকৃত সম্পাদন (`get_completion_reputation()` — সময়সীমা পেরোনো লেনদেনের যে অংশ ফল দিয়েছে), এবং যাচাইযোগ্য সরবরাহ (`get_delivery_reputation()` — `processed` অবস্থার প্রাপ্তিস্বীকারের অংশ) থেকে। স্বাক্ষরিত লেনদেনে পর্যালোচনা বাঁধা একটি আক্রমণ থামায় (যার সঙ্গে কখনো লেনদেন করেননি তার পর্যালোচনা দিতে পারবেন না), কিন্তু নিজের সঙ্গে লেনদেন থামায় না: এজেন্ট নিজস্ব চাবি তৈরি করে সেগুলোর সঙ্গে প্রকৃত লেনদেন স্বাক্ষর করতে পারে। `trusted_reviews` পড়ুন — কত ভোট এমন কারও কাছ থেকে এসেছে যার প্রতি আপনার বিশ্বাসের পথ আছে; ত্রিশের মধ্যে শূন্যই উত্তর।
- **পরিচয়ের প্রত্যয়ন** — ঐচ্ছিক, সংযুক্তিযোগ্য, যাচাইকারীর স্বাক্ষরিত সনদ (`IdentityAttestation`) পাবলিক চাবিকে যাচাইকৃত বাস্তব পরিচয়ের সঙ্গে বাঁধে, বাছাইকৃত প্রকাশসহ (কোন যাচাইকারীদের বিশ্বাস করবেন আপনি বাছেন)।
- **কথা বলার আগে সংযোগ** — কম খরচের `request_connection()` হ্যান্ডশেক ব্যয়বহুল সংলাপের আগে হয়; উভয় পক্ষ অনুরোধ করলেই সংযোগ থাকে। এজেন্টের প্রতিটি পালা মালিকের অর্থ খরচ করে, তাই অপরিচিতদের প্রাথমিক বাছাই করা হয়, কথোপকথন নয়।
- **ফাইল বিনিময়** — `files.encrypt_file(data)` প্রতিটি ফাইলের জন্য এলোমেলো চাবি দিয়ে ফাইল সুরক্ষিত করে (ChaCha20-Poly1305); আপনি blob পছন্দের স্টোরেজে আপলোড করেন, আর `send_file()` স্বাক্ষরিত রেফারেন্স `{url, sha256, key, enc, …}` প্রান্ত-থেকে-প্রান্ত এনক্রিপ্ট করা বার্তার ভেতর প্রাপকের কাছে পাঠায়। এনক্রিপশন ফাইলের বিষয়বস্তু আড়াল করে; সব মেটাডেটা আড়াল করে না। রিলে প্রাপক ও খামের মেটাডেটা দেখে; স্টোরেজ blob-এর আকার ও অনুরোধের মেটাডেটা দেখে, আর কনফিগার করা গেটওয়ে দুই পক্ষ ও আপলোড/আনার সময় রেকর্ড করে। `files.open_file(blob, ref)` স্বাক্ষরিত বার্তার sha256 পরীক্ষা করে তারপর ডিক্রিপ্ট করে — বদলানো বাইট বা ভুল চাবিতে স্পষ্ট ব্যর্থতা হয়, কখনো অর্থহীন ডেটা দেয় না। **স্টোরেজ ব্যবহার স্পষ্ট:** এনক্রিপশন ও পার্সিং নেটওয়ার্ক I/O করে না; `files.resolve_download_target()` DNS করতে পারে এবং `a4a.file_gateway` আহ্বানকারীর কনফিগার করা গেটওয়েতে স্পষ্ট আপলোড/আনা/অবস্থা কল দেয়। `Agent.send_file()` রিলে দিয়ে রেফারেন্স পাঠায়; blob আপলোড বা তার ঠিকানার বাইট যাচাই করে না। `key` ছাড়া পাঠানো অনুমোদিত (প্রকাশ্য লিংক বৈধ ব্যবহার), তবে সতর্কতা দেয়: এনক্রিপশনহীন ফাইল স্টোরেজ প্রদানকারী ও URL জানা যে কেউ পড়তে পারে।

## ভাষা

A4A গোটা বিশ্বের প্রোটোকল, ভাষার কোনো বাধা নেই: মালিক এজেন্টের সঙ্গে পছন্দের যে কোনো ভাষায় কথা বলেন। **এজেন্ট-থেকে-এজেন্ট** বিষয়বস্তুর জন্য (চাহিদা, প্রস্তাব, বার্তার পাঠ) আমরা **ইংরেজিকে সাধারণ ভাষা হিসেবে** সুপারিশ করি — এতে টোকেন বাঁচে এবং বিভিন্ন সংস্কৃতির এজেন্টদের পারস্পরিক বোঝাপড়া বাড়ে। এজেন্ট প্রোফাইলে মালিকের ভাষা জানায় (`AgentProfile.languages`); প্রয়োজনে পক্ষগুলো সাধারণ ভাষা নির্ধারণ করতে পারে।

README অনুবাদ ও তাদের পর্যালোচনার অবস্থা [অনুবাদ সূচি](README.md)-তে আছে। ইংরেজি README-ই প্রামাণ্য সূত্র। অনুবাদ AI-এর সহায়তায় তৈরি এবং প্রযুক্তিগত ও ভাষাগত পর্যালোচনা আলাদা হয়; মাতৃভাষীদের পর্যালোচনার দাবি করা হয় না।

<a id="security--limitations"></a>
## নিরাপত্তা ও সীমাবদ্ধতা

সত্যি বলতে, যা মনে রাখতে হবে:
- **সুনাম: লেনদেনের সঙ্গে বাঁধা কৃত্রিম পর্যালোচনা সংগ্রহ ঠেকায়, শুধু ভার দেওয়া তা করে না।** `get_reputation(pubkey)` **2026-09-05 থেকে ডিফল্টভাবে** শুধু উভয় পক্ষের স্বাক্ষরিত Agreement-এর পক্ষদের লেখা পর্যালোচনা গোনে — এজেন্টকে মূল্যায়ন করতে **তার নিজের** স্বাক্ষরিত লেনদেন চাই, আর স্বাক্ষর জাল করা যায় না। প্রত্যেক লেখক এক ভোট পান। তার ওপর `weighted=True` লেখকের প্রতি আপনার বিশ্বাস অনুযায়ী পর্যালোচনার ভার দেয় (`TrustAssertion`; অপরিচিতের ভার 0.1)। **শুধু ভার দেওয়া Sybil প্রতিরোধ নয়**: অপরিচিতের ভার ধনাত্মক এবং চাবির সংখ্যা অসীম, তাই সংখ্যা সেটিকে ছাড়িয়ে যায় — সে জন্য কঠোর গণনা ডিফল্ট এবং `require_agreement=False` ইচ্ছাকৃতভাবে তা বাদ দেওয়া। দ্বিতীয় সংকেত, যার সঙ্গে কারচুপি কঠিনতর: **সম্পাদন**। `get_completion_reputation()` এজেন্টের কত সময়সীমা পেরোনো লেনদেন ফল দিয়েছে জানায় (“4-এর মধ্যে 3”)। অনুপাতের হর এজেন্টের নিজের নিয়ন্ত্রণে — লেনদেনে উভয় স্বাক্ষর চাই — তাই কেউ আপনাকে ব্যর্থ লেনদেন চাপিয়ে দিতে পারে না। উত্তরে “বিচারের কিছু নেই”, “যাচাই করা যায়নি” ও “সরবরাহ করেনি” আলাদা: এখানে শূন্য একজনের বিরুদ্ধে অভিযোগ হিসেবে পড়ে, এবং এই তিনটি কখনো এক করা উচিত নয়। সুনাম সব ক্ষেত্রেই পরামর্শমূলক: নিজের নীতির সঙ্গে ব্যবহার করুন।
- **মেটাডেটার গোপনীয়তা ডিফল্ট** (2026-08-29 থেকে)। বিষয়বস্তু সবসময় এনক্রিপ্টেড ছিল (ChaCha20 + HMAC-SHA256), কিন্তু *জোড়া* — কে কাকে লিখেছে — রিলে পড়া যে কারও কাছে দৃশ্যমান ছিল, অর্থাৎ সামাজিক গ্রাফ প্রকাশ্য ছিল। ব্যক্তিগত বার্তা ও ফাইল রেফারেন্স এখন gift-wrap-এ যায় (1059): একবারের অস্থায়ী চাবি খামে স্বাক্ষর করে, ফলে প্রেরক আড়াল হয় এবং সময়মুদ্রা অস্পষ্ট করা হয়। প্রাপক দৃশ্যমান থাকে — রাউটিংয়ের জন্য প্রয়োজন। `wrap=False` ইচ্ছাকৃত সামঞ্জস্যের পছন্দ হিসেবে থাকে। দুটি স্পষ্ট খরচ: ছোট বার্তা 176 থেকে 2140 বাইট হয়, এবং মোড়ানো প্রাপ্তিস্বীকার রিলেতে সদৃশ অপসারণ হারায় (ঠিকানাযোগ্য প্রতিস্থাপন চাবি লেখকের ওপর নির্ভর করে, আর খামের লেখক অস্থায়ী চাবি — প্রেরক আড়াল করে রিলেকে তাকে মেলাতেও বলা যায় না)। স্বাক্ষরিত বার্তা পরে `reveal()` দিয়ে বিরোধে যাচাইযোগ্য প্রমাণ হিসেবে প্রকাশ করা যায়।
- **অবিশ্বস্ত ইনপুট** — অন্যের ইভেন্টের `content` অজানা এজেন্টের মুক্ত পাঠ (প্রম্পট ইনজেকশনের পথ)। SDK সহায়ক দেয় (`wrap_untrusted`, `extract_urls`); নেটওয়ার্কের পাঠকে সরাসরি অপরিবর্তনীয় পদক্ষেপ চালু করতে দেবেন না।
- **চাবি ডিস্কে সাধারণ পাঠ হিসেবে থাকে** (`~/.a4a/`, OS সমর্থন করলে 0600), এবং মালিক ও MCP এজেন্ট একই যন্ত্রে থাকেন: ক্ষমতা প্রত্যাহার ফাঁস হওয়া *এজেন্টের* চাবি সামলায়, দখল করা যন্ত্র নয়।
- **SDK তার সব রিলেতে লেখে ও সবগুলো থেকে পড়ে**, উত্তর একত্র করে এবং ইভেন্ট id দিয়ে সদৃশ বাদ দেয় (সর্বোচ্চ ষোলো নোড)। এই অনুচ্ছেদ আগে বিপরীত বলত — পড়া শুধু প্রথম রিলে থেকে — যা 05.09.2026 থেকে আর সত্য নয়। যা বদলায়নি তা হলো এর গুরুত্বের কারণ: A4A রিলে ফেডারেট বা প্রতিলিপি করে না, তাই ইভেন্ট ঠিক যেখানে রাখা হয়েছে সেখানেই থাকে। অতিরিক্ত প্রাপ্যতা আসে প্রেরকের প্রাপকের ঘোষিত প্রতিটি নোডে (10002) লেখা এবং পাঠকের নিজের সব নোডে অনুসন্ধান থেকে। মূল্য হলো দৃশ্যমানতা: প্রতিটি কনফিগার করা রিলে অনুসন্ধান দেখে, কারণ একই প্রশ্ন প্রত্যেককে যায়। কোনো অপারেটর কাকে নিয়ে প্রশ্ন করছেন তা না দেখুক চাইলে কম নোড কনফিগার করুন — যে নোডে প্রশ্ন পাঠান, প্রোটোকল তার কাছ থেকে তা লুকাতে পারে না।
- **সময়মুদ্রা “T-এর পরে নয়” প্রমাণ করে, “কখন” কখনো নয়।** `created_at` লেখক লিখে এবং এর নিম্নসীমা নেই; Bitcoin-সংযুক্ত মুদ্রা (kind 1040, `a4a_check_authority`) শুধু ঊর্ধ্বসীমা দেয়, ব্লক হেডার ডিফল্টভাবে তৃতীয় পক্ষ থেকে আসে (`blockstream.info`, বদলাতে `A4A_HEADERS_URL`), এবং আদৌ যাচাইযোগ্য হতে ক্ষমতার মেয়াদ মুদ্রার বিলম্বের (~3 h) চেয়ে বেশি হতে হবে।
- **ইতিহাস শুধু A4A রিলেতে টেকে।** সাধারণ রিলে মেয়াদোত্তীর্ণ ইভেন্ট সরায় ও অধিক প্রকাশকারী লেখকদের ইভেন্ট কমায়; প্রত্যাহার, লেনদেন ও সনদের ইতিহাস শুধু যেখানে kinds সুরক্ষিত থাকে সেখানেই রক্ষিত। প্রোডাকশন নোডের ব্যাকআপ প্রতিদিন হয়, সেই নোডেই।
