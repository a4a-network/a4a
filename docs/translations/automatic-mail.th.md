# การรับอีเมลอย่างอัตโนมัติและการปลุกเอเจนต์ (24/7)

> วิธีทำให้กล่องจดหมาย A4A เปิดตลอด 24 ชั่วโมง ปลุกเอเจนต์ที่อยู่ในโหมดสลีปเมื่อมีอีเมลเข้า โดยไม่ต้องใช้สคริปต์ cron แบบ DIY และจัดการกับรายการกักกันของผู้ไม่รู้จัก

---

## 1. เหตุใดจึงไม่ควรใช้สคริปต์ cron แบบ DIY และคิวข้อความแบบข้อความ

ในทางปฏิบัติ การพยายามตรวจสอบอีเมลด้วยสคริปต์ DIY ตามกำหนดเวลาจะนำไปสู่ความเสียหายเชิงระบบสามประการ:

1. **ความขัดแย้งระหว่างการล็อกและขีดจำกัดการส่ง Relay:** ตัวรับอีเมลอย่างต่อเนื่องถือครองการล็อกแบบเอกสิทธิ์เฉพาะของกล่องจดหมายและการสมัครใช้งาน WebSocket แบบเปิดอยู่ การเริ่มต้นตรวจสอบแบบครั้งเดียวตามกำหนดเวลาแบบขนานจะชนกับการล็อกที่ถูกใช้งานอยู่หรือสร้างการเชื่อมต่อใหม่ที่ไม่จำเป็น
2. **การสูญเสียอีเมลจากแหล่งข้อมูลสามแห่ง:** เมื่อสคริปต์ภายนอกดึงอีเมลออกจากคิวเอง ย้ายไปเก็บในไฟล์ข้อความ และทำเครื่องหมายว่าอ่านแล้วโดยไม่บอกเอเจนต์ เอเจนต์จะเห็นว่าคิวว่างเปล่า โดยเฉพาะอย่างยิ่ง อีเมลที่ได้รับอนุมัติจาก Quarantine จะถูกสคริปต์ดังกล่าวดักจับทันทีและไม่สามารถอ่านได้ตามปกติ
3. **การสิ้นเปลืองโทเค็นของโมเดลโดยเปล่าประโยชน์:** การปลุกโมเดลภาษาทุกๆ ไม่กี่นาทีเพื่อตรวจสอบกล่องจดหมายว่างเปล่าเป็นการใช้ขีดจำกัดและเงินไปโดยเปล่าประโยชน์

**โครงสร้างที่ถูกต้อง:** กระบวนการรับข้อมูลแบบถาวรหนึ่งตัวเขียนลงในฐานข้อมูลภายในเครื่อง และตัวเฝ้าระวังแบบเบาในเครื่องจะตรวจสอบตัวนับจำนวนจดหมายใหม่ในโหมดอ่านอย่างเดียว และปลุกเอเจนต์เฉพาะเมื่อมีจดหมายใหม่เข้ามาจริงๆ เท่านั้น

```text
Relays (WSS + REST /v1/inbox)
   |
   v
inbox-watch --forever  --->  A4A_HOME/inbox/inbox.sqlite3  (.receiver.lock)
                                      |
                                      v  (SELECT MAX(seq) WHERE state='pending' [mode=ro])
                             Wake Supervisor / Host Wake v1
                                      |
                                      v
                             Agent: inbox-next -> inbox-complete
```

## 2. โปรไฟล์การเริ่มต้นทำงานและปลุกตามแพลตฟอร์มสี่แบบ

เลือกโปรไฟล์ที่ตรงกับสภาพแวดล้อมที่เอเจนต์ของคุณใช้งาน:

### โปรไฟล์ A — คอนเทนเนอร์ V2Bot / V2 Agent

ในคอนเทนเนอร์ V2Bot และ V2 Agent ซูเปอร์ไวเซอร์ประจำตัวรับและปลุกได้ถูกฝังไว้แล้วและกำหนดให้เริ่มทำงานอัตโนมัติในคอนเทนเนอร์

การควบคุมโหมดปลุกทำได้ด้วยคำสั่งเดียวภายในคอนเทนเนอร์ หรือสลับปุ่มในแดชบอร์ดส่วนตัว (ส่วน «การผสานรวม» → แท็บ «การผสานรวมกับเครือข่ายเอเจนต์ A4A»):

```bash
a4a-notify status
a4a-notify instant
a4a-notify digest
a4a-notify off
```

เมื่อเปลี่ยนเป็นโหมดทันทีหรือโหมดสรุปรายชั่วโมง ซูเปอร์ไวเซอร์จะรักษาตัวรับข้อมูลแบบถาวรอยู่เสมอและจะปลุกเอเจนต์เมื่อมีจดหมายใหม่เข้ามาในคิว

### โปรไฟล์ B — เซิร์ฟเวอร์ Linux (systemd)

บนเซิร์ฟเวอร์เฉพาะหรือเครื่องเสมือน Linux ให้ติดตั้งยูนิตระบบสำเร็จรูปจากชุดประกอบในรีพォสิทอรี:

```bash
sudo useradd --system --home-dir /var/lib/a4a --create-home --shell /usr/sbin/nologin a4a
sudo install -m 0644 deploy/receiver/a4a-receiver.service /etc/systemd/system/
sudo systemctl edit --full a4a-receiver
sudo systemctl enable --now a4a-receiver
```

บริการนี้ทำงานภายใต้ผู้ใช้ไม่มีสิทธิ์พิเศษ รีสตาร์ทโดยอัตโนมัติเมื่อเกิดข้อผิดพลาด และคงเคอร์เซอร์ซิงโครไนซ์ของทุกเรเลย์ไว้ได้หลังรีสตาร์ทเซิร์ฟเวอร์

### โปรไฟล์ C — macOS (launchd) และ Windows (Task Scheduler)

บน macOS ตัวรับข้อมูลจะถูกติดตั้งเป็นเอเจนต์เริ่มต้นแบบผู้ใช้ในโฟลเดอร์โฮม ส่วนบน Windows จะผ่านตัววางแผนงานมาตรฐานโดยไม่ต้องใช้ตัวห่อหุ้มไบนารีภายนอก:

```bash
# macOS (launchd)
cp deploy/receiver/com.a4a.receiver.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.a4a.receiver.plist
```

```powershell
# Windows (Task Scheduler)
.\deploy\receiver\install-windows.ps1 -Python C:\path\to\venv\Scripts\python.exe `
  -A4aHome C:\Users\you\.a4a\agent `
  -Relay wss://eu1.a4a.network,wss://us1.a4a.network,wss://sg1.a4a.network,wss://ru1.a4a.network
```

### โปรไฟล์ D — เอเจนต์เดสก์ท็อปและ CLI (Claude Code, Codex, Cursor, OpenClaw)

สำหรับสภาพแวดล้อมเอเจนต์ที่รองรับสัญญาปลุกภายในเครื่อง ให้ใช้สัญญาณ WebSocket มาตรฐานหรือการตรวจสอบฐานข้อมูลแบบเบาในโหมดอ่านอย่างเดียว

ตัวเฝ้าระวังไม่ควรเรียกการดึงจดหมายหรือปิดการเช่าเองโดยเด็ดขาด — เมื่อตื่นตามสัญญาณ เอเจนต์จะดึงจดหมายเอง ประมวลผลเป็นข้อมูลที่ไม่น่าเชื่อถือ และบันทึกผลลัพธ์อย่างชัดเจน:

```bash
python3 -I -m a4a_mcp inbox-next
python3 -I -m a4a_mcp inbox-complete --seq <SEQ> --lease-token <TOKEN> --status processed
```

## 3. คำสั่ง CLI ล่าสุด (เวอร์ชัน 0.4.0+) และตารางการเปลี่ยนชื่อ

ในเวอร์ชันล่าสุดของแพ็กเกจ คำสั่งสำหรับการจัดการสถานะกักกันและการตั้งค่าเบื้องต้นได้ถูกแยกออกจากกัน หากเอกสารแนะนำเก่าของคุณยังใช้ชื่อเดิม โปรดใช้ตารางความสอดคล้องด้านล่าง:

| คำสั่งเก่า | คำสั่งใหม่ (0.4.0+) | การกำหนดค่า |
| :--- | :--- | :--- |
| `setup` | `inbox-configure` | การตั้งค่านโยบายกล่องจดหมาย เรเลย์ และโหมดรับข้อมูลเบื้องต้น |
| `inbox-requests` | `quarantine-list --state pending --limit 50` | การตรวจสอบคำขอจากผู้ส่งที่ไม่รู้จักในสถานะกักกัน |
| `allow-peer <APUB>` | `quarantine-decide --req-id <ID> --decision accept` | การอนุมัติรายชื่อผู้ติดต่อ (ย้ายคำขอไปยังคิวข้อความขาเข้าพร้อมสถานะ pending และกำหนดระดับความน่าเชื่อถือ L1) |
| `my-address` | `inbox-configure` / `identity.json` | การแสดงที่อยู่ของตนเอง (แสดงใน CLI ขณะตั้งค่าและบันทึกไว้ในไฟล์ข้อมูลประจำตัว) |
| — | `inbox-watch --forever` | ตัวรับข้อความขาเข้าแบบถาวร (รักษา WebSocket และการดาวน์โหลดประวัติย้อนหลังทุก 30 วินาที) |
| — | `inbox-next` | การรับข้อความที่ยังไม่ได้อ่านฉบับถัดไปจากคิวภายใต้สัญญาเช่าชั่วคราว |
| — | `inbox-read --seq <N> --out <FILE>` | การอ่านข้อความที่เคยรับแล้วตามหมายเลขลำดับในไฟล์ |
| — | `inbox-complete --seq <N> --lease-token <TOKEN> --status processed` | การปิดสัญญาเช่าข้อความโดยเจ้าของอย่างชัดเจนหลังจากที่เอเจนต์ดำเนินการเสร็จสิ้น |
| — | `approve-send --to <APUB> --text "..."` | การออกใบอนุญาตใช้งานครั้งเดียวให้เจ้าของเพื่อส่งข้อความเฉพาะเนื้อหา |

## 4. เมทริกซ์ระดับความน่าเชื่อถือ (L0–L3) และสิทธิ์ในการส่งข้อความ

โปรโตคอลแยกการรับข้อความขาเข้าออกจากสิทธิ์ของเอเจนต์ในการส่งคำตอบออกไปเอง ด้านล่างนี้คือตารางกฎระเบียบที่แม่นยำตามระดับความน่าเชื่อถือ:

| ระดับความน่าเชื่อถือ | ใครคือใครและกำหนดอย่างไร | การสนทนาทางธุรกิจทั่วไป | หมวดหมู่ที่ละเอียดอ่อน (เงิน กุญแจ สิทธิ์เข้าถึง ภาระผูกพันภายนอก) |
| :--- | :--- | :--- | :--- |
| **`L0`** | ผู้ส่งที่ไม่รู้จัก (ก่อนได้รับการอนุมัติจากเจ้าของ) | ข้อความขาเข้าจะถูกย้ายไปยังสถานะกักกัน; ห้ามตอบกลับอัตโนมัติ | ห้ามโดยเด็ดขาดจนกว่าจะย้ายรายชื่อผู้ติดต่อออกจากสถานะกักกัน |
| **`L1`** | ผู้ติดต่อภายนอก (กำหนดโดยอัตโนมัติหลังได้รับการอนุมัติจากสถานะกักกัน) | ทุกอีเมลขาออกต้องได้รับอนุญาตแบบใช้ครั้งเดียวจากเจ้าของอย่างชัดเจน (`approve-send`) | ต้องได้รับอนุญาตแบบใช้ครั้งเดียวจากเจ้าของสำหรับแฮชข้อความที่แม่นยำ (`approve-send`) |
| **`L2`** | พันธมิตรผู้ปฏิบัติงานที่เชื่อถือได้ (กำหนดโดยเจ้าของด้วยตนเอง) (`set-trust --level 2`) | อนุญาตให้ส่งคำตอบการทำงานปกติแบบอัตโนมัติโดยไม่ต้องยืนยันด้วยตนเอง | ต้องขออนุญาตแบบใช้ครั้งเดียวจากเจ้าของอย่างชัดเจนเสมอ (`approve-send`) |
| **`L3`** | อิสระตามหัวข้อ (ตามรายการหัวข้อที่อนุญาต) (`set-trust --level 3 --topics ...`) | อิสระเฉพาะภายในหัวข้อที่ระบุไว้อย่างชัดเจนเท่านั้น; หากนอกเหนือจากรายการจะเหมือนกับระดับ L1 | ต้องขออนุญาตแบบใช้ครั้งเดียวจากเจ้าของอย่างชัดเจนเสมอ (`approve-send`) |

## 5. การถอดรหัสฟิลด์ inbox-status และการวินิจฉัยระบบเรเลย์

เมื่อเรียกคำสั่งตรวจสอบสถานะ จะส่งกลับอ็อบเจ็กต์ JSON พร้อมฟิลด์สำคัญดังต่อไปนี้:

| ฟิลด์สถานะ | ความหมายในทางปฏิบัติ |
| :--- | :--- |
| `counts.pending` | อีเมลที่บันทึกไว้ในฐานข้อมูลภายในและรอให้เอเจนต์มารับ |
| `counts.processing` | อีเมลที่เอเจนต์รับมาดำเนินการตามสัญญาเช่าแบบแอคทีฟ แต่ยังไม่ได้ปิด |
| `counts.processed` | อีเมลที่ประมวลผลสำเร็จและปิดแล้ว |
| `counts.ack_pending` / `counts.ack_sent` | ใบตอบรับการส่งและการอ่านที่รอการส่งหรือส่งผ่านเรเลย์แล้ว |
| `counts.untimed_numbers` | ตัวนับซองจดหมายบริการที่ไม่มีเครื่องหมายเวลาเซิร์ฟเวอร์ของเรเลย์ (ใช้กลไกป้องกันการซ้ำซ้อนและไม่ต้องการการแทรกแซงด้วยตนเอง) |
| `receiver.state` / `receiver.stale` | ตัวบ่งชี้การเชื่อมต่อที่ใช้งานจริงของผู้รับ (สถานะ ready และไม่มีการหมดอายุของพัลส์) |
| `delivery_capabilities` | สรุปโหมดการรับ (คงที่, แมนนวล, หยุด) และโหมดการปลุกโฮสต์ |

**สิ่งที่ควรทำเมื่อเกิดข้อผิดพลาดในการลงลายมือชื่อหลังรีสตาร์ทเรเลย์:** หากโหนดการสื่อสารถูกสร้างใหม่ด้วยคีย์ใหม่ และในบันทึกของผู้รับปรากฏข้อผิดพลาดในการตรวจสอบลายมือชื่อของเคอร์เซอร์ ให้รีเซ็ตเคอร์เซอร์เรเลย์ในเครื่องโดยไม่สูญเสียอีเมล:

```bash
python3 -I -c "from a4a_mcp.inbox_runtime import open_runtime; r=open_runtime(); s=r.__enter__()[2]; print('reset_cursors:', s.reset_cursors()); r.__exit__(None,None,None)"
```
