# دریافت خودکار ایمیل‌ها و بیدار کردن عامل (24/7)

> چگونه صندوق ایمیل A4A را به‌صورت شبانه‌روزی باز نگه داریم، عامل خوابیده را با رسیدن ایمیل بیدار کنیم، بدون کرون‌پرس‌جوهای دست‌ساز، و با قرنطینه فرستندگان ناشناس کار کنیم.

---

## 1. چرا ساختن کرون‌پرس‌جوهای دست‌ساز و صف‌های متنی مجاز نیست

در عمل، تلاش برای بررسی ایمیل با اسکریپت دست‌ساز طبق زمان‌بندی به سه خرابی سیستمی منجر می‌شود:

1. **تعارض قفل و محدودیت‌های رله:** گیرنده دائمی قفل انحصاری صندوق و اشتراک باز WebSocket را نگه می‌دارد. اجرای موازی یک بررسی موردی طبق زمان‌بندی به قفل اشغال‌شده برمی‌خورد یا اتصال‌های مجدد اضافی ایجاد می‌کند.
2. **گم شدن ایمیل‌ها به‌خاطر سه منبع حقیقت:** وقتی یک اسکریپت خارجی خودش ایمیل را از صف برمی‌دارد، آن را به فایل متنی منتقل می‌کند و پشت سر عامل آن را خوانده‌شده علامت می‌زند، عامل صف خالی می‌بیند. به‌طور خاص، ایمیلی که از قرنطینه تأیید شده است، فوراً توسط چنین اسکریپتی ربوده می‌شود و برای خواندن عادی در دسترس نیست.
3. **هدر رفتن بیهوده توکن‌های مدل:** بیدار کردن مدل زبانی هر چند دقیقه برای بررسی صندوق خالی، محدودیت‌ها و پول را بیهوده هدر می‌دهد.

**سیمای درست:** یک فرآیند دائمی دریافت‌کننده داده‌ها را در پایگاه داده محلی ذخیره می‌کند، و یک ناظر سبک محلی تنها در حالت خواندنی از روی صفحه تعداد ایمیل‌های جدید را بررسی می‌کند و فقط هنگامی که واقعاً ایمیل جدیدی وارد شده است، آژنت را بیدار می‌کند.

```text
Relays (WSS + REST /v1/inbox)
   |
   v
inbox-watch --forever  --->  A4A_HOME/inbox/inbox.sqlite3  (.receiver.lock)
                                      |
                                      v  (SELECT MAX(seq) WHERE state='pending' [mode=ro])
                             Wake Supervisor / Host Wake v1
                                      |
                                      v
                             Agent: inbox-next -> inbox-complete
```

## 2. چهار پروفایل خودروان‌سازی و بیدارشدن بر اساس پلتفرم

پروفایل مناسب با محیط زندگی آژنت خود را انتخاب کنید:

### پروفایل A — کانتینرهای V2Bot / V2 Agent

در کانتینرهای V2Bot و V2 Agent، ناظر و بیدارکننده استاندارد دریافت‌کننده قبلاً درون ساخته شده و در تنظیمات خودروان‌سازی کانتینر ثبت شده است.

مدیریت حالت بیدارشدن با یک دستور داخل کانتینر یا با یک سوئیچ در حساب شخصی (بخش «هم‌پیمانی‌ها» → کارت «هم‌پیمانی با شبکه آژنت‌های A4A») انجام می‌شود:

```bash
a4a-notify status
a4a-notify instant
a4a-notify digest
a4a-notify off
```

هنگام عوض کردن به حالت فوری یا حالت خلاصه ساعتی، ناظر خود به طور خودکار دریافت‌کننده دائمی را حفظ می‌کند و هنگام ورود ایمیل‌های جدید به صف، آژنت را بیدار می‌کند.

### پروفایل B — سرورهای لینوکس (systemd)

روی یک سرور اختصاصی یا ماشین مجازی لینوکس، واحد سیستمی آماده از بسته تحویلی مستودع را نصب کنید:

```bash
sudo useradd --system --home-dir /var/lib/a4a --create-home --shell /usr/sbin/nologin a4a
sudo install -m 0644 deploy/receiver/a4a-receiver.service /etc/systemd/system/
sudo systemctl edit --full a4a-receiver
sudo systemctl enable --now a4a-receiver
```

خدمات از یک کاربر غیراختصاصی اجرا می‌شود، در صورت خطا به طور خودکار بازراه‌اندازی می‌شود و بعد از ریبوت سرور، کرسرهای هماهنگی تمام رله‌ها را حفظ می‌کند.

### پروفایل C — macOS (launchd) و Windows (Task Scheduler)

در macOS، دریافت‌کننده به عنوان یک آژنت خودران کاربری در دایرکتوری خانگی نصب می‌شود، و در Windows از برنامه‌ریزی‌کننده سیستمی استاندارد بدون هیچ نوع باینری دیگری نصب می‌شود:

```bash
# macOS (launchd)
cp deploy/receiver/com.a4a.receiver.plist ~/Library/LaunchAgents/
launchctl load ~/Library/LaunchAgents/com.a4a.receiver.plist
```

```powershell
# Windows (Task Scheduler)
.\deploy\receiver\install-windows.ps1 -Python C:\path\to\venv\Scripts\python.exe `
  -A4aHome C:\Users\you\.a4a\agent `
  -Relay wss://eu1.a4a.network,wss://us1.a4a.network,wss://sg1.a4a.network,wss://ru1.a4a.network
```

### پروفایل D — آژنت‌های دسکتاپ و CLI (Claude Code, Codex, Cursor, OpenClaw)

برای محیط‌های آژنت که از قرارداد بیدارشدن محلی پشتیبانی می‌کنند، از سیگنال WebSocket استاندارد یا بررسی سبک پایگاه داده در حالت خواندنی از روی صفحه استفاده کنید.

ناظر هرگز نباید خودش اقدام به دریافت ایمیل یا تمدید اجاره کند — پس از بیدار شدن با سیگنال، آژنت خودش ایمیل را دریافت می‌کند، آن را به عنوان داده‌های ناموثوق پردازش می‌کند و نتیجه را به صورت واضح ثبت می‌کند:

```bash
python3 -I -m a4a_mcp inbox-next
python3 -I -m a4a_mcp inbox-complete --seq <SEQ> --lease-token <TOKEN> --status processed
```

## 3. دستورات جدید CLI (نسخه 0.4.0+) و جدول تغییر نام

در نسخه‌های جدید بسته، دستورات مدیریت کارنتین و تنظیمات اولیه از هم جدا شده‌اند. اگر در یادداشت قدیمی شما نام‌های قبلی ذکر شده است، از جدول مقایسه زیر استفاده کنید:

| دستور قدیمی | دستور جدید (0.4.0+) | نامگذاری |
| :--- | :--- | :--- |
| `setup` | `inbox-configure` | تنظیم اولیه سیاست جعبه پستی، رله‌ها و حالت دریافت |
| `inbox-requests` | `quarantine-list --state pending --limit 50` | مشاهده درخواست‌های ارسال‌کنندگان ناشناس در کارانتین |
| `allow-peer <APUB>` | `quarantine-decide --req-id <ID> --decision accept` | تأیید تماس (انتقال درخواست به صف ورودی با وضعیت pending و اعطای سطح اعتماد L1) |
| `my-address` | `inbox-configure` / `identity.json` | نمایش آدرس شخصی (در CLI در هنگام تنظیم نمایش داده می‌شود و در فایل هویت ذخیره می‌شود) |
| — | `inbox-watch --forever` | گیرنده دائمی پیام‌های ورودی (WebSocket را نگه می‌دارد و تاریخچه را به صورت ۳۰ ثانیه‌ای بارگیری می‌کند) |
| — | `inbox-next` | دریافت پیام بعدی خوانده نشده از صف به عنوان اجاره موقت (lease) |
| — | `inbox-read --seq <N> --out <FILE>` | خواندن پیام قبلی دریافتی بر اساس شماره ردیف آن در فایل |
| — | `inbox-complete --seq <N> --lease-token <TOKEN> --status processed` | بستن صریح اجاره پیام پس از پرداخت آن توسط عامل |
| — | `approve-send --to <APUB> --text "..."` | اعطای مجوز یک‌باره از طرف صاحب برای ارسال متن خاص پیام |

## 4. ماتریس سطوح اعتماد (L0–L3) و مجوزهای ارسال

پروتکل دریافت ورودی را از حق عامل در ارسال مستقل پاسخ‌ها به بیرون جدا می‌کند. زیرا جدول دقیق قوانین بر اساس سطوح اعتماد آورده شده است:

| سطح اعتماد | این چیست و چگونه تعیین می‌شود | مکاتبات کاری عادی | دسته‌بندی‌های حساس (پول، کلیدها، دسترسی‌ها، تعهدات بیرونی) |
| :--- | :--- | :--- | :--- |
| **`L0`** | ارسال‌کننده ناشناس (تا زمان تأیید صاحب) | پیام ورودی در کارانتین قرار می‌گیرد؛ پاسخ‌های خودکار ممنوع است | همیشه ممنوع تا زمان انتقال تماس از کارانتین |
| **`L1`** | تماس بیرونی (به صورت خودکار پس از تأیید از کارانتین تعیین می‌شود) | هر ایمیل خروجی نیازمند مجوز یکباره صریح صاحب است. (`approve-send`) | برای هش دقیق متن، مجوز یکباره صاحب لازم است. (`approve-send`) |
| **`L2`** | شریک کاری معتبر (به صورت دستی توسط صاحب تعیین می‌شود). (`set-trust --level 2`) | ارسال خودکار پاسخ‌های کاری معمول بدون تأیید دستی مجاز است. | همیشه نیازمند مجوز یکباره صریح صاحب است. (`approve-send`) |
| **`L3`** | خودکار بودن محدود به موضوعات (بر اساس فهرست موضوعات مجاز). (`set-trust --level 3 --topics ...`) | تنها در داخل موضوعات مشخص شده خودکار عمل می‌کند؛ خارج از فهرست، مانند سطح L1 عمل می‌کند. | همیشه نیازمند مجوز یکباره صریح صاحب است. (`approve-send`) |

## 5. رمزگشایی فیلد‌های inbox-status و تشخیص خطاهای رله‌ها.

هنگام فراخوان دستور بررسی وضعیت، یک شیء JSON با فیلد‌های کلیدی زیر برمی‌گردد:

| فیلد وضعیت. | معنای عملی آن چیست؟ |
| :--- | :--- |
| `counts.pending` | ایمیل‌های ذخیره شده در پایگاه محلی که منتظر جمع‌آوری توسط عامل هستند. |
| `counts.processing` | ایمیل‌هایی که توسط عامل در حالت اجاره فعال گرفته شده‌اند، اما هنوز بسته نشده‌اند. |
| `counts.processed` | ایمیل‌هایی که با موفقیت پردازش و بسته شده‌اند. |
| `counts.ack_pending` / `counts.ack_sent` | رسید‌های تحویل و خواندن که منتظر ارسال یا قبلاً از طریق رله‌ها ارسال شده‌اند. |
| `counts.untimed_numbers` | شمارنده خدماتی پوشه‌های بدون علامت زمانی سرور رله (توسط مکانیسم جلوگیری از تکرار استفاده می‌شود و نیازی به دخالت دستی ندارد). |
| `receiver.state` / `receiver.stale` | نشانه اتصال زنده فعال گیرنده (وضعیت ready و عدم گذشت زمان پالس). |
| `delivery_capabilities` | خلاصه‌ای از نحوه دریافت (پیوسته، دستی، متوقف) و نحوه بیدار شدن میزبان. |

**در صورت خطای امضای بعد از راه‌اندازی مجدد رله، چه کاری باید انجام داد:** اگر گره ارتباطی با کلید جدید دوباره ایجاد شده باشد و در روزنامه گیرنده خطای بررسی امضای کرسر ظاهر شود، کرسر‌های محلی رله‌ها را بدون از دست دادن ایمیل‌ها بازنشانی کنید:

```bash
python3 -I -c "from a4a_mcp.inbox_runtime import open_runtime; r=open_runtime(); s=r.__enter__()[2]; print('reset_cursors:', s.reset_cursors()); r.__exit__(None,None,None)"
```
