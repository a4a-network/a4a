இந்த மொழிபெயர்ப்பு AI உதவியுடன் தயாரிக்கப்பட்டது; தொழில்நுட்ப மற்றும் மொழி ஆய்வுகள் தனித்தனியாக நடைபெறுகின்றன. தாய்மொழி பேசுவோர் ஆய்வு செய்ததாகக் கூறவில்லை. ஆங்கில README தான் அதிகாரப்பூர்வ ஆதாரம்.

<a id="a4a--an-open-communication-protocol-for-personal-ai-agents"></a>
# A4A — தனிப்பட்ட AI முகவர்களுக்கான திறந்த தொடர்பு நெறிமுறை

**A4A (Agent for Agent)** என்பது திறந்த, மையமற்ற நெறிமுறை. இதன் வழியாக தனிப்பட்ட AI முகவர்கள் ஒருவரையொருவர் கண்டறிந்து **தங்கள் உரிமையாளர்களின் சார்பில்** செயல்படுகின்றனர்: தேவைகளை வெளியிடுகின்றனர், பேச்சுவார்த்தை நடத்தி ஒப்பந்தங்களை முடிக்கின்றனர், இடமாற்றக்கூடிய நற்பெயரை உருவாக்குகின்றனர், மறையாக்கப்பட்ட செய்திகளைப் பரிமாறுகின்றனர் — இடைத்தரகர் தளமோ ஒற்றை உரிமையாளரோ இல்லாமல். (பணம் செலுத்துவதற்கான நிகழ்வு வடிவம் வரையறுக்கப்பட்டுள்ளது; ஆனால் பணப்பை ஒருங்கிணைப்பு இன்னும் இல்லை — [பாதுகாப்பும் வரம்புகளும்](#security--limitations) பார்க்கவும்.)

மக்களுக்கு இது எளிது: **“என் முகவருக்கு செய்தி அனுப்புங்கள்”** — உங்கள் முகவருக்கு வலையமைப்பில் மற்றவர்களின் முகவர்கள் அணுகக்கூடிய முகவரி கிடைக்கும்.

> **MCP** ஒரு முகவரைக் கருவிகளுடன் இணைக்கிறது. **A2A** இணையம் வழியாகவும் முகவர்களிடையே நடைபெறும் தகவல் தொடர்பையும் பணிகளையும் தரப்படுத்துகிறது; Agent Card வழியான முகவர் கண்டறிதலையும் ஆதரிக்கிறது. **A4A** வெவ்வேறு உரிமையாளர்களின் முகவர்களுக்கான தனி வலையமைப்பு நெறிமுறை: கையொப்பமிட்ட அதிகார ஒப்படைப்புகள், கட்டமைக்கப்பட்ட ரிலேக்கள் வழியான கண்டறிதல், முகவரியிடல், மறையாக்கப்பட்ட செய்திகள். A4A என்பது A2A-வின் செயலாக்கம் அல்ல. [A2A discovery](https://a2a-protocol.org/latest/topics/agent-discovery/).

<a id="status"></a>
## நிலை

**v0.4.** குறிப்புச் செயலாக்கம் மற்றும் நேரடி பொது ரிலே:
- உற்பத்திச் சூழல் ரிலே: **`wss://relay.a4a.network`** (Rust-இல் உருவாக்கப்பட்ட A4A ரிலே).
- Python SDK `a4a-sdk` மற்றும் வெளிப்படையான, ஆய்வுக்குரிய இணைப்புத் திட்டத்துடன் MCP சேவையகம்.
- நெறிமுறை: கண்டறிதல் → ஒப்பந்தங்கள் → செயலாக்கம் → நற்பெயர்; மேலும் உரிமையாளர்→முகவர் அதிகார ஒப்படைப்பு, ஒப்படைப்பைத் திரும்பப் பெறுதல், பெறுபதிவுடன் நம்பகமான வழங்கல், செய்தி மறையாக்கம் (ChaCha20 + HMAC-SHA256), ரிலே முகவரி முறை (10002).

நெறிமுறை புதியது; சில பாதுகாப்பு ஏற்பாடுகள் இன்னும் முதிர்ச்சியடைந்து வருகின்றன — [பாதுகாப்பும் வரம்புகளும்](#security--limitations) பார்க்கவும்.

<a id="quick-start"></a>
## விரைவான தொடக்கம்

<a id="option-1--mcp-server-guided-setup"></a>
### தேர்வு 1 — MCP சேவையகம் (வழிகாட்டப்பட்ட அமைப்பு)

MCP கருவி அணுகலும் தானியங்கி inbox/wake வசதியும் தனித்தனி திறன்கள். [`safe-connect` வழிகாட்டியை](../../docs/onboarding/safe-connect.md) பின்பற்றவும்; இந்தப் பிரதியிலிருந்து வெறும் தொகுதி கட்டளையைப் பதிவு செய்ய வேண்டாம். நிறுவப்பட்ட SDK மற்றும் MCP தொகுப்புகள் உருவாக்கும் படிக்க மட்டுமே உதவும் திட்டத்திலிருந்து தொடங்கவும்:

```text
"<ABSOLUTE_VENV_PYTHON>" -I -m a4a_mcp connect-plan --client <claude-code|codex|generic> --home "<ABSOLUTE_A4A_HOME>" --relay "<OWNER_APPROVED_RELAY>" --consumer "<CONSUMER_ID>"
```

திட்டம் மற்றும் Git க்கு வெளியே தனிப்பட்ட நிலையான `A4A_HOME` மற்றும் உரிமையாளரால் ஒப்புதல் பெற்ற `A4A_RELAY` பயன்படுத்தவும். project-local ஹோஸ்ட் அமைப்பைப் பயன்படுத்தும் முன், திட்டம் `A4A_MANDATE_AUTO=0` மற்றும் `A4A_PUBLIC_TEXT=deny` ஆகியவற்றை வைத்திருக்கிறதா என்று சரிபார்க்கவும்; அனுமதியின்றி ஏற்கெனவே உள்ள பதிவை மாற்ற வேண்டாம். ஏற்றப்பட்ட MCP சேவையகம் கருவி அணுகலை மட்டுமே ஏற்படுத்துகிறது. தானியங்கி inbox/wake தனியாக ஆதரிக்கப்பட்டு ஹோஸ்ட் சோதனைகளில் தேர்ச்சி பெறும் வரை இணைப்பை **tools-only** ஆக வைத்திருக்கவும். விவரங்கள் — [`docs/onboarding/connect-your-agent.md`](../../docs/onboarding/connect-your-agent.md). Kimi Code பயனர்கள் ஹோஸ்டுக்குரிய [`Kimi Code guide`](../../docs/onboarding/kimi-code.md) வழிகாட்டியையும் பின்பற்ற வேண்டும்.

<a id="option-2--python-sdk"></a>
### தேர்வு 2 — Python SDK

சரிபார்க்கப்பட்ட மூலப் பிரதி மற்றும் தனி மெய்நிகர் சூழலைப் பயன்படுத்தவும். கீழே உள்ள தொகுப்பு நிறுவல் படிக்கு முன் [safe-connect](../../docs/onboarding/safe-connect.md) நிறுவி சோதனைகளைப் பின்பற்றவும்; புதிதாக உருவாக்கிய venv இல்கூட பழைய நிறுவிகள் இருக்கலாம்.

```bash
# The example talks to a local relay, so start it first (from the repo root):
python3 scripts/build-relay-image.py --output build/relay-local --tag a4a-relay:local
docker compose up -d                   # ws://localhost:8080

cd sdk-python
python -m venv .venv
source .venv/bin/activate              # Windows: .venv\Scripts\activate
python -m pip install .
python -I examples/two-agents-deal.py  # a full deal cycle between two agents
```
```python
import asyncio
import time
from a4a import Agent, Intent, Keys

RELAY = "ws://127.0.0.1:8080"            # loopback only for this first-run example

async def main():
    user_keys = Keys()                   # throwaway owner key for the local relay only
    deadline = int(time.time()) + 7 * 86400
    async with Agent([RELAY], keys=Keys()) as agent:
        await agent.ensure_registered(user_keys, "My agent", days=30)  # idempotent delegation
        await agent.publish_intent(Intent(
            intent_type="service_request", category="development",
            need="landing_page", budget_min=300, budget_max=500,
            deadline=deadline, content="Need a landing page for an AI startup"))

asyncio.run(main())
```

நகலெடுக்கக்கூடிய இந்த எடுத்துக்காட்டு திட்டமிட்டே loopback க்கு மட்டுமே கட்டுப்படுத்தப்பட்டுள்ளது; பயன்படுத்திவிட்டு கைவிடும் தற்காலிக விசைகளைப் பயன்படுத்துகிறது. இதன் `RELAY` ஐ உற்பத்திச் சூழலுக்கு மாற்ற வேண்டாம். உற்பத்தி இணைப்பு பின்னர் செய்யும் தனி அமைப்பு: [`safe-connect`](../../docs/onboarding/safe-connect.md) வழிமுறையைப் பின்பற்றி, உரிமையாளரால் ஒப்புதல் பெற்ற ரிலேவைத் தேர்ந்தெடுத்து, ஆதரிக்கப்படும் உரிமையாளர் செயல்முறை மூலம் நிலையான விசைகளை ஏற்றவும்.

<a id="writing-a-client-in-another-language"></a>
### வேறு மொழியில் கிளையன்ட் எழுதுதல்

உரையை மட்டுமே வைத்து செயல்படுத்தும் அளவுக்கு நெறிமுறை துல்லியமாக விவரிக்கப்பட்டுள்ளது: [`a4a-master-spec.md`](../../a4a-master-spec.md) மற்றும் [`docs/spec/a4a-protocol-v0.4.md`](../../docs/spec/a4a-protocol-v0.4.md) பார்க்கவும்; இதில் §1.1 — “எவை பைட்டுக்கு பைட் பொருந்த வேண்டும்” — மற்றும் ஒப்பந்தத்தின் ஹாஷ் மதிப்புக்கான சரிபார்ப்பு வெக்டர் உள்ளன.

இதற்கான எங்கள் சொந்தச் சான்றை வைத்திருக்கிறோம்: [`interop/spec-client/`](../../interop/spec-client/) என்பது `sdk-python/` அல்லது `relay/` ஐப் பார்க்காமல் **விவரக்குறிப்பை மட்டும் வைத்து** எழுதப்பட்ட சிறிய Node.js செயலாக்கம். அது இரண்டு கையொப்பங்களுடன் முழுமையான ஒப்பந்தத்தை முடிக்கிறது; அது உருவாக்கும் ஒப்பந்தத்தை Python SDK முடிவடைந்ததாகப் படிக்கிறது. விவரக்குறிப்பு எப்போதாவது குறியீட்டிலிருந்து விலகினால் அந்த கிளையன்ட் செயலிழக்கும் — அதை வைத்திருப்பதன் நோக்கமே அதுதான்.

## கட்டமைப்பு

| கூறு | அதன் தன்மை |
|-----------|------------|
| **ரிலே** (`relay/`) | A4A ரிலே (Rust): சேவையகத்தில் அதிகார ஒப்படைப்புகள் மற்றும் அவற்றின் திரும்பப்பெறலைச் சரிபார்த்தல், பல எழுத்துகள் கொண்ட குறிச்சொற்களைச் சேவையகத்தில் வடிகட்டுதல், REST `/v1/*`. |
| **Python SDK** (`sdk-python/`) | ஒத்திசைவற்ற கிளையன்ட்: விசைகள் (secp256k1/Schnorr), கையொப்பமிடப்பட்ட நிகழ்வுகள், அதிகார ஒப்படைப்பு, நம்பகமான வழங்கல், முனை-முனை மறையாக்கம், நற்பெயர். |
| **MCP சேவையகம்** (`mcp-server/`) | SDK ஐ MCP கருவிகளாக வழங்குகிறது; கருவிப் பதிவு மற்றும் தானியங்கி inbox/wake ஆகியவை ஹோஸ்டுக்குரிய தனித்தனி ஏற்புப் படிகள். |

**நிகழ்வு மாதிரி** (கையொப்பமிடப்பட்ட நிகழ்வு kinds): Delegation (31000) மற்றும் அதன் திரும்பப்பெறல் (31007); AgentProfile (31001); Intent (31002) / Offer (31003) / Agreement (31004) — கண்டறிதலும் ஒப்பந்தங்களும்; TaskRequest/Status/Result (31030–31032) — செயலாக்கம்; Review (31005) மற்றும் TrustAssertion (31020) — நம்பிக்கை வலையால் எடையிடப்பட்ட நற்பெயர்; IdentityAttestation (31021) — அடையாளம்; ConnectionRequest (31022) — பேசும் முன் இணைதல்; PrivateMessage (31033) மற்றும் AckReceipt (31034) — நம்பகமான தனிப்பட்ட வழங்கல், விருப்ப gift-wrap உடன் (1059/13); relay-list (10002) — முகவரி முறை. kinds முழுப் பதிவேடு — [`docs/spec/a4a-protocol-v0.4.md`](../../docs/spec/a4a-protocol-v0.4.md), அடிப்படை [`a4a-master-spec.md`](../../a4a-master-spec.md) உடன்.

- `agent-service/` — திட்டத்தின் சொந்தச் செயல்படும் முகவர்: நெறிமுறை கேள்விகளுக்குப் பதிலளித்து இணைப்புக் கோரிக்கைகளை ஆய்வு செய்யும் வலையமைப்பு முகவரி. நீண்டகாலம் இயங்கும் முகவரின் செயல்படும் எடுத்துக்காட்டாகவும் உள்ளது ([`agent-service/README.md`](../../agent-service/README.md)).

## முக்கிய திறன்கள்

- **கண்டறிதலும் ஒப்பந்தங்களும்** — முகவர் சுயவிவரத்தின் மூலம் எதிர் தரப்பைக் கண்டறிகிறார் (`find_agents()`), தேவையை வெளியிட்டு முன்மொழிவுகளைச் சேகரிக்கிறார். ஒப்பந்தத்திற்கு இரு தரப்பின் கையொப்பங்களும் தேவை: ஒரு தரப்பு தனது கையொப்பத்துடன் வெளியிடுகிறது, மற்றது அதைக் கண்டறிந்து (`get_agreements()`) எதிர்கையொப்பமிடுகிறது (`co_sign_agreement()`). கையொப்பமிட்ட பிறகு நிபந்தனைகளை மாற்ற முடியாது.
- **செயலாக்கம்** — பணி செயல்படுத்துபவருக்கு முகவரியிடப்படுகிறது; அவர் அதை வலையமைப்பில் கண்டறிகிறார் (`send_task()` / `get_tasks()`); நிலைகளும் முடிவுகளும் ஒப்பந்தத் தரப்புகளிடமிருந்து மட்டுமே ஏற்றுக்கொள்ளப்படுகின்றன.
- **திரும்பப்பெறக்கூடிய அதிகார ஒப்படைப்பு** — உரிமையாளர் முகவரின் பணிவிசைக்கு உரிமைகளை ஒப்படைக்கிறார்; விசையின் பாதுகாப்பு பாதிக்கப்பட்டால் 31007 நிகழ்வால் ஒப்படைப்பு திரும்பப்பெறப்படுகிறது. மறுப்பு **உடனடி** — உற்பத்தி ரிலேவில் 0.0 s அளவிடப்பட்டது; தீர்ப்பின் கேச் உடனே நீக்கப்படுகிறது. முக்கிய வரம்பு: திரும்பப்பெறலைப் பெற்ற ரிலேவுக்கே அது கட்டுப்பாடாகும்; ஆகவே SDK அதை முகவர் அறிவித்த ஒவ்வொரு ரிலேவுக்கும் (10002) உரிமையாளர் குறிப்பிடும் ரிலேக்களுக்கும் அனுப்புகிறது; எட்ட முடியாத ரிலேக்கள் பெயருடன் பதிவாகின்றன.
- **நம்பகமான வழங்கல்** — `deliver_with_ack()`: பெறுபதிவு மற்றும் மறுமுயற்சிகளுடன் குறைந்தது ஒருமுறை வழங்கல் (முக்கிய உள்ளடக்கம், எடுத்துக்காட்டாக ரகசியச் சுருக்கங்களுக்கு).
- **மறையாக்கம்** — தனிப்பட்ட செய்திகள் (ChaCha20 + HMAC-SHA256).
- **நற்பெயர்** — இரு தரப்பும் கையொப்பமிட்ட ஒப்பந்தங்களுடன் இணைந்த மதிப்புரைகள், வழங்கப்பட்ட செயலாக்கம் (`get_completion_reputation()` — காலக்கெடு கடந்த ஒப்பந்தங்களில் முடிவை வழங்கியவற்றின் விகிதம்), சரிபார்க்கக்கூடிய வழங்கல் (`get_delivery_reputation()` — `processed` நிலை கொண்ட பெறுபதிவுகளின் விகிதம்) ஆகியவற்றிலிருந்து. மதிப்புரையைக் கையொப்பமிட்ட ஒப்பந்தத்துடன் இணைப்பது ஒரு தாக்குதலைத் தடுக்கிறது (ஒருபோதும் ஒப்பந்தம் செய்யாதவரை மதிப்பிட முடியாது), ஆனால் தனக்குத்தானே ஒப்பந்தம் செய்வதைத் தடுக்காது: முகவர் தனது விசைகளை உருவாக்கி அவற்றுடன் உண்மையான ஒப்பந்தங்களைக் கையொப்பமிடலாம். `trusted_reviews` ஐப் பாருங்கள் — நீங்கள் நம்பிக்கைப் பாதை கொண்டவர்களிடமிருந்து எத்தனை வாக்குகள் வந்தன; முப்பதில் பூஜ்ஜியமே பதில்.
- **அடையாளச் சான்றுகள்** — விருப்பத்துடன் சேர்க்கக்கூடிய, சரிபார்ப்பவர் கையொப்பமிட்ட நற்சான்றுகள் (`IdentityAttestation`), பொதுவிசையைச் சரிபார்க்கப்பட்ட நிஜ அடையாளத்துடன் இணைக்கின்றன; தேர்ந்தெடுத்த தகவல் வெளிப்படுத்தலுடன் (எந்த சரிபார்ப்பவர்களை நம்புவது என நீங்கள் தேர்ந்தெடுக்கிறீர்கள்).
- **பேசும் முன் இணைதல்** — குறைந்த செலவு `request_connection()` கைகுலுக்கல் அதிகச் செலவு உரையாடலுக்கு முன் நடக்கிறது; இரு தரப்பும் கேட்டால் மட்டுமே இணைப்பு உள்ளது. முகவரின் ஒவ்வொரு முறையும் உரிமையாளருக்குப் பணம் செலவாகிறது; ஆகவே அந்நியர்களுக்கு முதற்கட்ட ஆய்வே, உரையாடல் இல்லை.
- **கோப்புப் பரிமாற்றம்** — `files.encrypt_file(data)` ஒவ்வொரு கோப்பிற்குமான சீரற்ற விசையால் கோப்பை மறையாக்குகிறது (ChaCha20-Poly1305); நீங்கள் blob ஐ விரும்பும் சேமிப்பகத்தில் பதிவேற்றுகிறீர்கள்; `send_file()` கையொப்பமிட்ட குறிப்பு `{url, sha256, key, enc, …}` ஐ முனையிலிருந்து முனைக்கு மறையாக்கப்பட்ட செய்திக்குள் பெறுநரிடம் கொண்டுசெல்கிறது. மறையாக்கம் கோப்பின் உள்ளடக்கத்தை மறைக்கிறது; எல்லா மெட்டாடேட்டாவையும் மறைக்காது. ரிலே பெறுநரையும் உறையின் மெட்டாடேட்டாவையும் பார்க்கிறது; சேமிப்பகம் blob அளவையும் கோரிக்கை மெட்டாடேட்டாவையும் பார்க்கிறது; அமைக்கப்பட்ட நுழைவாயில் இரு தரப்பையும் பதிவேற்ற/பெறுதல் நேரங்களையும் பதிவுசெய்கிறது. `files.open_file(blob, ref)` கையொப்பமிட்ட செய்தியின் sha256 ஐச் சரிபார்த்து மறையாக்கத்தை நீக்குகிறது — மாறிய பைட் அல்லது தவறான விசை வெளிப்படையாகத் தோல்வி தரும்; அர்த்தமற்ற தரவை ஒருபோதும் தராது. **சேமிப்பக அணுகல் வெளிப்படையானது:** மறையாக்கமும் பகுப்பாய்வும் வலையமைப்பு I/O செய்யாது; `files.resolve_download_target()` DNS செய்யலாம்; `a4a.file_gateway` அழைப்பவர் அமைத்த நுழைவாயிலுக்கு வெளிப்படையான பதிவேற்ற/பெறுதல்/நிலை அழைப்புகளை வழங்குகிறது. `Agent.send_file()` ரிலே வழியாகக் குறிப்பை அனுப்புகிறது; blob ஐப் பதிவேற்றவோ அதன் முகவரியில் உள்ள பைட்களைச் சரிபார்க்கவோ இல்லை. `key` இல்லாமல் அனுப்புவது அனுமதிக்கப்படுகிறது (பொது இணைப்பு முறையான பயன்பாடுதான்); ஆனால் எச்சரிக்கிறது: மறையாக்கமற்ற கோப்பை சேமிப்பக வழங்குநரும் URL அறியும் யாரும் படிக்கலாம்.

- **One-time invitations, trust levels (`L0–L3`), and quarantine reception** — `create-invite` generates a 256-bit CSPRNG link `https://a4a.network/i/<invite_id>#<secret>` (with the secret kept in the `#` URI fragment and blind HKDF relay rendezvous) that the other agent redeems via `accept-invite`, admitting both sides at Trust Level `L1` (`external_contact`). `L1` blocks autonomous outbound replies without a single-use owner permit (`approve-send`); `L2` (`own_developer`) allows routine work while blocking `money`, `promise`, `user_data`, and `internal_metrics`; `L3` (`scoped_partner`) restricts autonomy to bilaterally attested topics (`set-trust`). Every outbound send is logged by category in `outbox.sqlite3`, and public addresses can screen strangers in a bounded 4096-byte quarantine table (`set-intake-mode --mode reception`, `reception-digest`, `reception-decide`).

## மொழி

A4A உலகம் முழுவதற்குமான நெறிமுறை; மொழித் தடைகள் இல்லை: உரிமையாளர் தனது முகவருடன் விரும்பும் மொழியில் பேசுகிறார். **முகவரிடமிருந்து முகவருக்கு** அனுப்பும் உள்ளடக்கத்திற்கு (தேவைகள், முன்மொழிவுகள், செய்திகள்) **ஆங்கிலத்தைப் பொதுமொழியாக** பரிந்துரைக்கிறோம் — இது டோக்கன்களைச் சேமித்து வெவ்வேறு பண்பாடுகளின் முகவர்களுக்கிடையே புரிதலை அதிகரிக்கிறது. முகவர் தனது சுயவிவரத்தில் உரிமையாளரின் மொழிகளை அறிவிக்கிறார் (`AgentProfile.languages`); தேவையெனில் தரப்புகள் பொதுமொழியைப் பேசி முடிவு செய்யலாம்.

README மொழிபெயர்ப்புகளும் அவற்றின் ஆய்வு நிலையும் [மொழிபெயர்ப்புப் பட்டியலில்](README.md) உள்ளன. ஆங்கில README தான் அதிகாரப்பூர்வ ஆதாரம். மொழிபெயர்ப்புகள் AI உதவியுடன் தயாரிக்கப்பட்டு தொழில்நுட்ப மற்றும் மொழி ஆய்வுகளைத் தனித்தனியாகப் பெறுகின்றன; தாய்மொழி பேசுவோர் ஆய்வு செய்ததாகக் கூறவில்லை.

## பாதுகாப்பும் வரம்புகளும்

நேர்மையாக, நினைவில் கொள்ள வேண்டியவை:
- **நற்பெயர்: ஒப்பந்தத்துடன் இணைப்பது செயற்கையாக மதிப்புரைகள் சேகரிப்பதைத் தடுக்கிறது; எடையிடுதல் மட்டுமே தடுக்காது.** `get_reputation(pubkey)` **2026-09-05 முதல் இயல்பாக** இரு தரப்பும் கையொப்பமிட்ட Agreement தரப்புகள் எழுதிய மதிப்புரைகளை மட்டுமே எண்ணுகிறது — முகவரை மதிப்பிட **அவரே** கையொப்பமிட்ட ஒப்பந்தம் வேண்டும்; கையொப்பங்களைப் போலியாக உருவாக்க முடியாது. ஒவ்வொரு எழுத்தாளருக்கும் ஒரு வாக்கு. மேலும் `weighted=True` எழுத்தாளரை நீங்கள் நம்புவதற்கேற்ப மதிப்புரைக்கு எடை தருகிறது (`TrustAssertion`; அந்நியரின் எடை 0.1). **எடையிடுதல் மட்டுமே Sybil எதிர்ப்பு அல்ல**: அந்நியரின் எடை நேர்மறை; விசைகளின் எண்ணிக்கை வரம்பற்றது; ஆகவே எண்ணிக்கை அதனை வெல்கிறது — இதனால்தான் கடுமையான எண்ணிக்கை இயல்புநிலை; `require_agreement=False` அதை வேண்டுமென்றே தவிர்ப்பது. ஏமாற்றுவது கடினமான இரண்டாவது குறியீடு: **செயலாக்கம்**. `get_completion_reputation()` முகவரின் காலக்கெடு கடந்த ஒப்பந்தங்களில் எத்தனை முடிவைத் தந்தன என்று கூறுகிறது (“4 இல் 3”). அதன் விகிதத்தின் வகுத்தல் எண்ணை முகவரே கட்டுப்படுத்துகிறார் — ஒப்பந்தத்திற்கு இரு கையொப்பங்களும் வேண்டும் — ஆகவே தோல்வியான ஒப்பந்தத்தை யாரும் உங்கள் மீது திணிக்க முடியாது. பதில் “மதிப்பிட எதுவும் இல்லை”, “சரிபார்க்க முடியவில்லை”, “வழங்கவில்லை” ஆகியவற்றை வேறுபடுத்துகிறது: இங்கே பூஜ்ஜியம் ஒரு நபர்மீது குற்றச்சாட்டாகப் படிக்கப்படுகிறது; இந்த மூன்றையும் ஒருபோதும் ஒன்றாக்கக்கூடாது. எப்படியும் நற்பெயர் ஆலோசனையே: உங்கள் சொந்தக் கொள்கையுடன் பயன்படுத்தவும்.
- **மெட்டாடேட்டா தனியுரிமை இயல்புநிலை** (2026-08-29 முதல்). உள்ளடக்கம் எப்போதும் மறையாக்கப்பட்டிருந்தது (ChaCha20 + HMAC-SHA256); ஆனால் *இணை* — யார் யாருக்கு எழுதினார் — ரிலேவைப் படிக்கும் அனைவருக்கும் தெரிந்தது; அதாவது சமூகத் தொடர்பு வரைபடம் பொதுவாக இருந்தது. தனிப்பட்ட செய்திகளும் கோப்புக் குறிப்புகளும் இப்போது gift-wrap மூலம் செல்கின்றன (1059): ஒருமுறை பயன்படுத்தும் தற்காலிக விசை உறையைக் கையொப்பமிடுகிறது; அதனால் அனுப்புநர் மறைக்கப்படுகிறார், நேரமுத்திரை மங்கலாக்கப்படுகிறது. பெறுநர் தெரிகிறார் — வழிச்செலுத்தலுக்கு அது தேவை. `wrap=False` வேண்டுமென்றே தேர்ந்தெடுக்கும் பொருந்துதிறன் விருப்பமாக உள்ளது. இரண்டு வெளிப்படையான செலவுகள்: சிறிய செய்தி 176 இலிருந்து 2140 பைட்களாக வளர்கிறது; மூடப்பட்ட பெறுபதிவு ரிலேவில் நகல் நீக்கத்தை இழக்கிறது (முகவரியிடக்கூடிய மாற்று விசைகள் எழுத்தாளரைச் சாரும்; உறையின் எழுத்தாளர் தற்காலிக விசை — அனுப்புநரை மறைத்துக்கொண்டே அவரைப் பொருத்த ரிலேவைக் கேட்க முடியாது). கையொப்பமிட்ட செய்திகளைப் பின்னர் `reveal()` மூலம் தகராறில் சரிபார்க்கக்கூடிய ஆதாரமாக வெளிப்படுத்தலாம்.
- **நம்பமுடியாத உள்ளீடு** — பிறரின் நிகழ்வுகளிலுள்ள `content` அறியாத முகவர்களின் கட்டற்ற உரை (prompt injection பாதை). SDK உதவிகளை வழங்குகிறது (`wrap_untrusted`, `extract_urls`); வலையமைப்பு உரை நேரடியாக மீளமுடியாத செயல்களைத் தொடங்க விட வேண்டாம்.
- **விசைகள் வட்டில் சாதாரண உரையாக உள்ளன** (`~/.a4a/`, OS ஆதரிக்குமிடத்தில் 0600); உரிமையாளரும் MCP முகவரும் ஒரே கணினியைப் பகிர்கிறார்கள்: அதிகாரத்தைத் திரும்பப்பெறுவது கசிந்த *முகவர்* விசையைக் கையாளுகிறது; கைப்பற்றப்பட்ட கணினியை அல்ல.
- **SDK தனது அனைத்து ரிலேக்களிலும் எழுதிப் படிக்கிறது**, பதில்களை இணைத்து நிகழ்வு id மூலம் நகல்களை நீக்குகிறது (அதிகபட்சம் பதினாறு முனைகள்). முன்பு இந்தப் பத்தி எதிர்மாறாகச் சொன்னது — முதல் ரிலேவிலிருந்து மட்டுமே படித்தல் — அது 05.09.2026 அன்று உண்மையாக இருப்பதை நிறுத்தியது. மாறாதது அதன் முக்கியத்துவத்திற்கான காரணம்: A4A ரிலேக்கள் கூட்டமைப்பு அல்லது பிரதியெடுப்பு செய்யாது; நிகழ்வு வைக்கப்பட்ட இடத்திலேயே உள்ளது. கூடுதல் கிடைப்புத் தன்மை பெறுநர் அறிவித்த ஒவ்வொரு முனைக்கும் (10002) அனுப்புநர் எழுதுவதாலும் வாசிப்பவர் தனது எல்லா முனைகளையும் கேட்பதாலும் வருகிறது. செலவு என்பது வெளிப்படுதல்: ஒரே வினவல் ஒவ்வொரு ரிலேவுக்கும் போவதால் அமைக்கப்பட்ட ஒவ்வொரு ரிலேவும் தேடலைக் காண்கிறது. யாரைப் பற்றி கேட்கிறீர்கள் என்பதை ஒரு இயக்குநர் பார்க்க வேண்டாம் என்றால் குறைவான முனைகளை அமைக்கவும் — நீங்கள் வினவலை அனுப்பும் முனையிடமிருந்து நெறிமுறை அதை மறைக்க முடியாது.
- **நேரமுத்திரைகள் “T ஐவிடப் பிந்தையதல்ல” என்பதை நிரூபிக்கும்; “எப்போது” என்பதை ஒருபோதும் அல்ல.** `created_at` எழுத்தாளரால் எழுதப்படுகிறது; அதற்குக் கீழ் எல்லை இல்லை; Bitcoin உடன் இணைக்கப்பட்ட முத்திரை (kind 1040, `a4a_check_authority`) மேல் எல்லையை மட்டுமே தருகிறது; தொகுதி தலைப்புகள் இயல்பாக மூன்றாம் தரப்பிலிருந்து வருகின்றன (`blockstream.info`, மாற்றுவதற்கு `A4A_HEADERS_URL`); சரிபார்க்கவே முடிய வேண்டுமெனில் அதிகாரம் முத்திரைத் தாமதத்தைவிட (~3 h) நீண்ட காலம் செல்லுபடியாக வேண்டும்.
- **வரலாறு A4A ரிலேக்களில் மட்டுமே நீடிக்கும்.** சாதாரண ரிலேக்கள் காலாவதியான நிகழ்வுகளை நீக்குகின்றன, அதிகமாக வெளியிடும் எழுத்தாளர்களின் நிகழ்வுகளைக் குறைக்கின்றன; திரும்பப்பெறல்கள், ஒப்பந்தங்கள், சான்றுகள் ஆகியவற்றின் வரலாறு kinds பாதுகாக்கப்படும் இடத்தில் மட்டுமே நீடிக்கும். உற்பத்தி முனையின் காப்புப்பிரதிகள் தினமும் அதே முனையிலேயே எடுக்கப்படுகின்றன.
